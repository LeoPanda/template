# 技術要件定義書 (TECHNICAL_REQUIREMENTS)

- **主担当エージェント**: 📐 設計・立案スペシャリスト (`architect`)
- **実装担当**: 💻 バックエンドエンジニア (`backend-engineer`), 🎨 UI/UXデザイナー (`ui-designer`)
- **副担当・監査**: 🛡️ 品質・テスト & QA (`qa-engineer`)
- **承認ゲート**: 👤 ユーザーによる明示的承認必須

## 1. システムアーキテクチャ全体像

本システムは、**2層構造システムプロファイル体系（第1層: 定常的コア設計規範 ＋ 第2層: 展開プロファイル）**に基づき、初期スケルトンコード（`skeletons/`）を展開した上で構築される。

### 1.1 第1層: 定常的コア設計規範 (Universal Core Specifications V2.4)
全システム・全プロファイル共通で最初から組み込むべき普遍的標準：
1. **フロント/バック責務分離構造 (Anti-God Component / Module)**:
   - フロントエンド: ディレクトリを `components/`, `hooks/`, `services/`, `types/`, `utils/` に物理分割し、**1ファイル最大250行制限**を厳守。
   - バックエンド: **1ファイル最大400行制限**（推奨250〜300行以内）を厳守。DTO構造体およびパーサーは独立モジュール（`schemas/`, `*_dto.rs` 等）へ物理分離し、Controller/ハンドラー層はオーケストレーションに専念させ、直書きモックを排除してDBアクセス層やヘルパーへ委譲する。
2. **型定義自動同期パイプライン**:
   - バックエンドの FastAPI (OpenAPI) 定義から TypeScript 型定義を自動生成する（`npm run codegen:types`）。手動型定義によるタイポや二重管理を排除。
3. **環境変数・シークレット厳格バリデーション**:
   - Pydantic Settings による起動時型バリデーション。プレースホルダー（`[YOUR_KEY]` 等）混入時は即座に例外を発生させて安全停止する。
4. **統一タイムゾーン運用**:
   - データベース内部および API 通信は **Aware UTC（ISO 8601 文字列 `YYYY-MM-DDTHH:MM:SSZ`）** で統一。UI表示層においてのみ JST (日本標準時) へ変換する。
5. **自動CIワークフロー (GitHub Actions)**:
   - `.github/workflows/ci.yml` による PR/Push 契機の Lint、型チェック、単体/スモークテストの自動実行。
6. **構造化ロギング & クラッシュ耐性**:
   - JSTタイムスタンプおよび UUIDv4 `log_id` を自動バインドした構造化JSONログ出力。
7. **モック制御アダプター層 (案C＋案A & Fail-Fast原則)**:
   - 環境変数 `VITE_ENABLE_MOCK=true/false` による明示的切替と、コンポーネント内直書きモックの原則禁止。実結合モード（`false`）におけるサイレントモックフォールバックを厳格禁止し、エラー時は例外を即スローしてUI/ログに顕在化させる。
8. **画面グランドデザイン規範 & デイライト視認性**:
   - [01_グランドデザイン基本仕様書.md](./グランドデザイン/01_グランドデザイン基本仕様書.md) に準拠した 4px/8px グリッド体系および HEX/px絶対値併記。
   - デイライトモード視認性担保のためセマンティックデザイントークンまたはTailwindの明暗ペア（`bg-blue-50 text-blue-800 dark:bg-blue-950/40 dark:text-blue-300`）を必須とし、ダーク前提淡色カラーの単独直書きを禁止。

### 1.2 第2層: システム展開プロファイル (Deployment Profile)

- **選定プロファイル**: **[Profile A / Profile B / Profile C / Profile D]**

#### Profile A (サーバーレス極小コストWeb型 / 最優先ゴールデンパス) 詳細構成
- **コンテナ・インフラ**: Google Cloud Run（マルチステージビルド単一コンテナ、React静的配信 ＋ FastAPI バックエンド）。
- **データ永続化**: SQLite (`/data/app.db`)。WALモード有効化 (`PRAGMA journal_mode=WAL;`)、ビジータイムアウト設定 (`PRAGMA busy_timeout=5000;`)、外部キー制約有効化 (`PRAGMA foreign_keys=ON;`)。
- **レプリケーション**: Litestream による GCS (Google Cloud Storage) バケットへの WAL 非同期継続バックアップ。
  - **最大インスタンス数制約**: 単一ライター制約保護のため `max-instances=1` に固定。
  - **バケット名の一意化**: `<project-id>-litestream-<container-name>`。
- **マイグレーション**: **Alembic 標準統合**。生SQL手動DDLを完全排除し、マイグレーションリビジョンを Git 管理。
- **確定起動シーケンス (`entrypoint.sh`)**:
  1. Litestream リストア（GCS上にレプリカが存在する場合に復元）
  2. `alembic upgrade head`（起動時マイグレーション自動適用）
  3. Litestream レプリケーションプロセス起動（バックグラウンド）
  4. Uvicorn アプリケーション起動（フォアグラウンド）
- **認可・セキュリティ (IAP JWT 二重防御)**:
  - Google Cloud IAP による前段認証。
  - バックエンド層（`core/auth.py`）で `X-Goog-IAP-JWT-Assertion` ヘッダーの公開鍵署名を検証し、ユーザー情報（Email/Sub）を抽出。ローカル開発環境（`DEBUG=True`）時のみ安全なモックユーザーへ自動切替。
- **可観測性・内部監視**:
  - `/api/internal/health`: 死活監視および SQLite 疎通確認。
  - `/api/internal/litestream/status`: 最終レプリケーション同期ラグ監視。
- **外部API二重キャッシュ**:
  - TTL インメモリキャッシュ ＋ SQLite テーブルキャッシュによる二重防御。

#### 他プロファイルの構成要約
- **Profile B (Web SSR / フルマネージドRDB型)**: Next.js/Nuxt SSR または FastAPI + Cloud SQL (PostgreSQL) + Alembic。
- **Profile C (静的MPA / 超軽量ツール型)**: FastAPI + Jinja2 + HTMX / 単一バイナリCLI。
- **Profile D (PCローカルデスクトップアプリ型)**: Tauri v2 + Local SQLite + Frameless TitleBar + IStorageAdapter。

## 2. 各レイヤの技術スタック詳細

### 2.1 データベースレイヤ
- **エンジン**: SQLite 3.40+ (WALモード)
- **マイグレーションツール**: Alembic 1.13+
- **ORM**: SQLAlchemy 2.0+ (Declarative Base, Mapped 型アノテーション)
- **セッション管理**: `core/db/session.py` によるスコープ付きセッション (`scoped_session` / `sessionmaker`)
- **規約**:
  - 生SQLによるテーブル作成・変更（`CREATE TABLE`, `ALTER TABLE`）は**絶対禁止**。
  - すべてのテーブルに `id` (PK), `created_at` (UTC), `updated_at` (UTC) を付与。
  - 将来のマルチユーザー化に備え、必要に応じて `user_id` カラムを設計に含める。

### 2.2 バックエンドレイヤ
- **言語・実行環境**: Python 3.11+ / Uvicorn
- **フレームワーク**: FastAPI
- **主要モジュール構成**:
  - `core/config.py`: Pydantic Settings による環境変数ロード・バリデーション。
  - `core/auth.py`: IAP JWT署名検証依存性 (`get_current_user`)。
  - `core/cache.py`: 外部API二重キャッシュデコレーター。
  - `api/v1/`: 業務ドメイン別APIルーター。
  - `api/internal/`: 死活監視および Litestream 同期ラグ監視。
- **構造化ロギング**: JST日時・`log_id` (UUIDv4) バインド。動的ログレベル変更 API (`POST /api/internal/logger/level`)。

### 2.3 フロントエンドレイヤ
- **フレームワーク**: React 18+ (SPA) + Vite
- **言語**: TypeScript 5.0+ (Strictモード)
- **スタイリング**: Tailwind CSS + [01_グランドデザイン基本仕様書.md](./グランドデザイン/01_グランドデザイン基本仕様書.md) 準拠デザイントークン
- **アイコン**: Lucide React (ミニマルアイコン表示、英語 Tooltip 統一)
- **モック制御**: MSW (Mock Service Worker 2.0+)
  - `src/mocks/browser.ts`: Service Worker 起動
  - `src/mocks/handlers.ts`: モックエンドポイント定義
  - `main.tsx`: `import.meta.env.VITE_ENABLE_MOCK === 'true'` で MSW を初期化
- **画像最適化**: `useImageCompressor` フックによる 700×700px 正方形 WebP (80%品質) 事前圧縮。

## 3. 標準コマンドシーケンス (Standard Command Sequences)

エージェントおよび開発者が実行する標準コマンドシーケンスを以下に統一規定する。

```bash
# 1. Alembic マイグレーション生成 (モデル変更後)
docker compose exec backend alembic revision --autogenerate -m "<リビジョン名>"

# 2. Alembic マイグレーション適用
docker compose exec backend alembic upgrade head

# 3. OpenAPI からの TypeScript 型定義自動同期
docker compose exec frontend npm run codegen:types

# 4. CI 同等ローカル検証 (コミット前ゲート)
docker compose exec backend ruff check .
docker compose exec backend pytest
docker compose exec frontend npm run lint
docker compose exec frontend npm run type-check

# 5. コンテナ再構成 (設定・依存パッケージ変更時)
docker compose down && docker compose up --build -d
```

## 4. セキュリティおよび認証・シークレット管理

1. **二重防御認可**: 前段 IAP 認証に加え、アプリ層での JWT 署名検証を必須化。
2. **平文シークレットの排除**:
   - Gitリポジトリから `.env`, 秘密鍵 JSON, `app.db` を完全除外 (`.gitignore`)。
   - 本番環境では GCP Secret Manager から Cloud Run へ環境変数として注入。
3. **本番リリース時のモック無効化**:
   - 本番用 `.env.production` または Dockerfile ビルド引数で `VITE_ENABLE_MOCK=false` を強制設定し、モックハンドラーの混入を二重防御。

## 5. E2E / 結合テスト環境

- `tests/e2e/` に Playwright テスト環境を整備。
