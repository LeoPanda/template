### 1.3 ２層構造システム展開プロファイル (System Deployment Profile V2.4)

本システムは、以下の2層構造システムプロファイル体系に基づき設計・構築されます。

#### 【第1層: 定常的コア設計規範 (Universal Core Specifications)】
いかなる規模・プロファイルであっても、技術的負債化を防止するために無条件で初期配置・遵守する普遍的規範：
1. **フロント/バック責務分離構造 (Anti-God Component / Module)**: フロントエンド1ファイル最大250行制限、バックエンド1ファイル最大400行制限（DTO・パーサーの独立モジュール物理分離、Controller層はオーケストレーションに専念）。
2. **型定義自動同期パイプライン**: OpenAPI (FastAPI) スキーマから TypeScript 型定義を自動生成 (`npm run codegen:types`)。
3. **環境変数・シークレット厳格バリデーション**: Pydantic Settings による起動時検証。プレースホルダー混入時の即時停止ガード。
4. **統一タイムゾーン運用**: DB保存およびAPI通信は Aware UTC (ISO8601)、UI表示時のみ JST へ変換。
5. **自動CIワークフロー**: GitHub Actions による Lint, 型チェック, 単体・スモークテストのコミット前・自動検証。
6. **構造化ロギング & クラッシュ耐性**: JSTタイムスタンプ・UUIDv4 `log_id` 自動バインド。
7. **モック制御アダプター層 (Fail-Fast原則)**: 環境変数 `VITE_ENABLE_MOCK=true/false` による明示的切替 (案C) とコンポーネント内直書きモックの原則禁止 (案A)。実結合モード（`false`）でのサイレントモックフォールバック厳格禁止。
8. **画面グランドデザイン規範 & デイライト視認性**: 4px/8px グリッド体系、HEX/px絶対値併記、ウィンドウ形態選定基準の遵守。デイライトモード視認性担保のためセマンティックデザイントークンまたはTailwind明暗ペア指定を必須化し、ダーク前提淡色カラーの単独直書きを禁止。

| :--- | :--- | :--- | :--- |

## 2. システムの機能要件

### 2.1 ダッシュボード機能
- システム主要データのサマリー表示、視覚的なインジケーター/グラフィック、注意喚起ドットマーク、および直近のアクティビティをリアルタイムに把握できるようにします。

### 2.2 リアルタイム横断検索機能
- 管理対象および各種マスターデータを、キーワード（名称、識別コード、概要、備考等）によってリアルタイムにインクリメンタル絞り込み・検索できる機能を備えます。

### 2.3 マスタ管理機能
- 各種区分・分類等のマスタデータを画面から登録・編集・削除可能とします（外部キー制約に基づく削除保護付き）。

### 2.4 一覧・詳細画面機能
- 各種データの一覧画面を設け、デスクトップ（テーブル）↔ モバイル（カード型グリッド）のハイブリッド表示、ソート機能、および詳細表示/インライン編集/モーダル編集を提供します。

### 2.5 外部システム・API連携 & キャッシュ機能
- 外部API連携を伴う場合、TTLメモリキャッシュ ＋ DBキャッシュの二重キャッシュ機構を設け、レートリミット対策および外部サービス障害耐性を確保します。

## 3. 非機能要件・セキュリティ・運用保守

### 3.1 認証・認可およびアクセス制御
- **Profile A 選定時**: Google Cloud Run の Identity-Aware Proxy (IAP) による前段認証に加え、FastAPIバックエンド層（`core/auth.py`）において `X-Goog-IAP-JWT-Assertion` トークンの公開鍵署名検証を二重防御として必須実装します（開発環境 `DEBUG=True` 時のみ安全なローカルモックへ自動フォールバック）。

### 3.2 データベース永続化・マイグレーション・バックアップ構成 (Profile A)
- **SQLite WALモード**: `PRAGMA journal_mode=WAL;`, `PRAGMA busy_timeout=5000;`, `PRAGMA foreign_keys=ON;` による高信頼ローカルDB運用。
- **Alembic マイグレーション厳格運用**: スキーマ変更における生SQL手動DDLを完全排除し、Alembicによる自動リビジョン生成・追跡を徹底。
- **Litestream レプリケーション**: コンテナ起動時の確定リストアおよび稼働中のGCS非同期継続レプリケーション。
- **Cloud Run 設定制約**:
  - `max-instances=1` (SQLite 単一ライター制約保護)
  - バックアップ用GCSバケット名の一意化 (`<project-id>-litestream-<container-name>`)

### 3.3 モックアップ制御アーキテクチャ (案C＋案A)
- **環境変数切替 (案C)**: `.env` の `VITE_ENABLE_MOCK=true` (開発・モック時) / `false` (実API結合・本番時) により、MSW (Mock Service Worker) によるインターセプトと実通信を透過的に切り替えます。
- **直書きモックの原則禁止 (案A)**: UIコンポーネント内へのダミーデータ配列や擬似ステートの直書きを排除し、すべて `src/mocks/` に集約します。

### 3.4 内部監視・可観測性
- 死活監視エンドポイント (`GET /api/internal/health`)
- Litestream同期ラグ監視エンドポイント (`GET /api/internal/litestream/status`)

## 4. UI/UX・グランドデザイン標準仕様

### 4.1 デザイントークン & レイアウト規格
- **グランドデザイン全面準拠**: [01_グランドデザイン基本仕様書.md](./グランドデザイン/01_グランドデザイン基本仕様書.md) に規定されたセマンティックカラー（Blue `#2563eb`, Slate `#0f172a`, Emerald `#059669`, Rose `#e11d48` 等）および 4px/8px グリッドを厳格適用。
- **メインコンテナ**: デスクトップ表示時 `max-w-[1800px] mx-auto`。
- **ウィンドウ形態選定基準**: 簡易確認・マスタ追加は「標準モーダル」、複合編集は「スライドインドロワー」、デスクトップ時は「スプリットペイン / Frameless TitleBar」を採用。

### 4.2 テーマ切り替え機能（マルチテーマ）
- 「ライトモード」「ダークモード」「システム (OS設定追従)」の 3 つの表示モード切替をサポート。

### 4.3 ボタン類のミニマルアイコン化および英語Tooltip表記ルール
- 操作ボタン（Edit, Delete, Search, Sync 等）はアイコンのみのミニマル表示とし、英語表記（Title Case）のツールチップ (`title`) を付与。

### 4.4 画像最適化仕様
- 画像アップロード時はブラウザ側 Canvas API により **700px × 700px 正方形 WebP (80%品質)** に事前圧縮して送信。
