# PHASE 3: 基本設計書の作成とドキュメント整合性チェック

要件定義書に基づき、以下の基本設計書を作成および精査してください。

## 1. 設計書雛形の配置と作成
プラグインの `templates/` から以下の4ドキュメントを `docs/` に保存・作成してください。
- `技術要件定義書.md`
- `ビジネスロジック仕様書.md`
- `画面仕様書.md`
- `テーブルスキーマ定義書.md`

`docs/要件定義書.md`、`docs/AI駆動ロギングシステム仕様書.md`、`docs/APIキー安全管理・一元化設計書.md` の情報を踏まえ、各設計ドキュメントを本プロジェクト用に完全な記述として完成させてください。

> [!IMPORTANT]
> 要件定義書に表された機能を実現するための技術要件が要件定義書にも技術要件定義書にも不足している場合は、そのことを Artifacts に明示して指示を待ってください。


## 2. ドキュメント相互の自動整合性チェック（Self-Healing Loop）
設計書が出揃った後、`dev-doc-reviewer` スキルの解析ロジックを読み出し、以下の検証を自動実行してください。

1. `docs/` 配下の全ドキュメントを比較精査し、矛盾点・誤植・説明不足を検出。
2. 検出結果を Artifacts にリストアップ。
3. 矛盾点が解消されるまで、ドキュメントの補正と再検証を自律的に繰り返す。
