# PHASE 2: 要件定義書の作成および清書 V2.2

- **主担当エージェント**: 📐 設計・立案スペシャリスト (`architect`) (Model: `pro`)
- **委譲元 / 統括**: 👑 プロジェクトコンダクター (`conductor`)
- **承認ゲート**: 👤 ユーザーによる明示的承認必須

本スキルは、`docs/要件定義書.md` の精査・詳細化および清書を支援・実行します。

---

## 作業手順

1. **ドキュメントの読み込み**:
   - `docs/要件定義書.md` および `docs/` 配下の背景知識ドキュメントを読み込んでください。
2. **2層プロファイル体系の適用と展開プロファイル選定**:
   - **第1層 (定常的コア設計規範)**: 以下の8項目を非機能要件欄に無条件で自動バインドしてください。
     1. フロントエンド責務分離構造 (Anti-God Component / 1ファイル最大250行制限)
     2. 型定義自動同期パイプライン (`openapi-typescript` による `npm run codegen:types`)
     3. 環境変数・シークレット厳格バリデーション (Pydantic Settings)
     4. 統一タイムゾーン運用 (Aware UTC保存 / JST表示規約)
     5. 自動CIワークフロー (GitHub Actions)
     6. 構造化ロギング & クラッシュ耐性
     7. モック制御アダプター層 (環境変数 `VITE_ENABLE_MOCK` 切替 & 直書きモック排除)
     8. 画面グランドデザイン基礎規範 (4px/8pxグリッド、HEX/px絶対値併記)
   - **第2層 (展開プロファイル選定ディシジョンツリー)**:
     - Q0: AIエージェント用スキル・スクリプト（SKILL.md / Python CLI / PKM自動化）の開発か？ ➔ Yes: **Profile E** (Web/DB要件適用除外、Zero-Dependency Python + 2系統分離設計)
     - Q1: PCローカル環境（オフライン・ネイティブファイルアクセス等）での動作が必須か？ ➔ Yes: **Profile D**
     - Q2: フロントとバックエンドの単一プロセス・ビルドレス運用（HTMX等）が最優先か？ ➔ Yes: **Profile C**
     - Q3: 高頻度同時書き込みやSEO/SSRが必須か？ ➔ Yes: **Profile B**
     - それ以外（個人〜小規模SaaS、月額極小コスト、単一ライター保護で十分） ➔ **Profile A (ゴールデンパス)**
3. **要件定義書の清書・構造化**:
   - 目的、システムの概要、2層プロファイル体系、機能要件、非機能要件、外部インターフェース要件、制約事項について具体的に清書してください。
4. **レビューと未決事項（Open Questions）の抽出**:
   - 曖昧な仕様やユーザー確認が必要な事項がある場合は、標準完了サマリの「残課題 / Open Questions」に明記してください。
5. **標準完了サマリの返却 (Single Writer原則)**:
   - 作業完了後、コンダクターに対して完了サマリを返送してください。コンダクターが `PROJECT_STATE.md` を更新し、ユーザー承認ゲートを提示します。
