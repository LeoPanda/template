# Wiki知見永続化・RCA (wiki-maintainer) スキル

- **主担当エージェント**: 🛡️ 品質・テスト & 監査・QAスペシャリスト (`qa-engineer`) (Model: `pro`)
- **委譲元 / 統括**: 👑 プロジェクトコンダクター (`conductor`)
- **適用契機**: 設計レビュー不合格、コード品質指摘、テスト失敗、自律修復ループ発生時
- **厳格な記録境界ガードレール**: **知見の記録先は必ずプロジェクトローカルの `./wiki/` 配下に限定する。** グローバル領域への直接書き込みは絶対に行わない。

---

## 1. 入力情報
- エラーログ、スタックトレース、テスト失敗出力
- レビュー結果報告書（不合格要因、指摘箇所）
- 試行錯誤履歴、環境設定やライブラリのトラップ

---

## 2. 処理手順

### Step 1: 根本原因分析 (RCA - Root Cause Analysis)
表層のエラーメッセージだけでなく、「なぜ発生したか」「どのような設計・実装の落とし穴があったか」を掘り下げて特定する。

### Step 2: 二層分離（Two-Tier Separation）の仕分け判定
獲得した知見を以下の2つの層に厳格に分類する：

1. **Tier 1: プロジェクト固有仕様 (Local Domain / Specs)**
   - 業務ロジックの特殊仕様、個別画面の特有制約、対象システムの個別DB定義など。
   - 配置先: `./wiki/patterns/local/PAT-LOC-xxx_{識別名}.md`
   - **正本化フロー**: 各フェーズ完了ゲートにおいて `docs/`（仕様書・設計書）および `PROJECT_STATE.md` へ逆同期し、推論エージェントは設計書経由で消費する。
2. **Tier 2: 汎用パターン・共通落とし穴 (Universal Patterns / Pitfalls)**
   - フレームワーク挙動、Docker/コンテナ仕様、型安全性、共通テスト手順、エージェント行動規範。
   - 配置先: `./wiki/patterns/universal/PAT-{CAT}-xxx_{識別名}.md` (CAT: ERR, SYS, SEC, TEST等)
   - **昇格フロー**: PHASE 8 において `wiki-proposer` が読み込み、`skills/` や `rules/` の改善パッチとして起案される。

### Step 3: パターンファイルの作成・記録
所定のMarkdown形式でパターンファイルを生成する。

```markdown
# [PAT-CAT-xxx]: パターン概要タイトル

- **登録日**: YYYY-MM-DD
- **分類**: Tier 1 (プロジェクト固有) / Tier 2 (汎用共通)
- **発生契機**: [PHASE 3 レビュー / PHASE 6 テスト / 自律修復]
- **影響コンポーネント**: [バックエンドAPI / フロントエンド / Docker 等]

## 1. 事象とエラー内容
[発生したエラーの抜粋や現象]

## 2. 根本原因 (RCA)
[表面的な事象ではなく、真の発生原因]

## 3. 回避策・解決パターン
[具体的な修正方法、設定値、コードスニペット]

## 4. 再発防止ルール
[設計書記載ルールや実装規範]
```

### Step 4: 台帳ファイルの更新
- `./wiki/logs.md`: 発生事象、作成パターンID、仕分け結果を時系列で追記。
- `./wiki/skill-impact.md`: 影響するスキルやコンポーネントを記録。

---

## 3. 標準完了サマリの返却

コンダクターへ以下の形式でサマリを返送してください。

```markdown
## 作業完了サマリ
- **担当エージェント**: qa-engineer
- **実施フェーズ / タスク**: Wiki知見永続化・RCA (`wiki-maintainer`)
- **生成パターンID**: PAT-CAT-xxx
- **分類結果**: Tier 1 (local) / Tier 2 (universal)
- **保存先パス**: ./wiki/patterns/...
- **根本原因 (RCA) 概要**:
  - [エラーの根本原因と再発防止策]
- **台帳更新**: ./wiki/logs.md, ./wiki/skill-impact.md 更新完了
```
