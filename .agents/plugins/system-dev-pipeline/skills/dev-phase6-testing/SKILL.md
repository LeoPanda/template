# PHASE 6: スルーテスト環境の構築と自動テスト実施

自動テストスイートおよびシナリオテストを構築・実行し、すべてのテストがPassするまで修復ループを実行してください。

## 作業手順

1. **シナリオテスト計画書の作成**:
   - プラグインの `templates/シナリオテスト計画書.md` を `docs/plans/シナリオテスト計画書.md` に保存してください。
   - `docs/` 配下の仕様に基づき、テストシナリオ・評価基準を完成させてください。

2. **テスト環境およびテストコードの構築**:
   - テストフレームワーク（E2E / Integration / Unit）をセットアップし、シナリオに基づいたテストコードを作成してください。

3. **自動テストの実行と修復ループ（Self-Healing Loop）**:
   - テストを非同期・自動実行してください。
   - 自律修復の対象は**「テストスクリプト」**および**「テスト・開発環境設定」**に関わる不具合に限定します。
   - **コンテナ再構成の徹底**: テスト環境設定やコードの修復・変更を行った後は、**必ず `docker compose down` および `docker compose up --build -d` を実行して Docker コンテナをビルド・再構成**した上でテストを再実行してください。
   - **「システムのプログラムコード」**に起因する不具合・エラーを発見した場合は、勝手にコード修正を行わず、原因調査レポートを Artifacts に明示してユーザーの指示を仰いでください。ユーザー指示によりプログラムコードを修正した場合も、**必ず `docker compose down` および `docker compose up --build -d` でコンテナをビルド・再構成**してください。
   - 修復ループの反復は**最大5回まで**とし、5回を超えてもテストが成功しない場合は処理を中断し、状況を Artifacts に詳細レポートしてください。


4. **最終ドキュメント整合性レビュー**:
   - テスト完了後、`dev-doc-reviewer` スキルを自動起動し、修正コードとドキュメント間の整合性を最終確認・補正してください。
