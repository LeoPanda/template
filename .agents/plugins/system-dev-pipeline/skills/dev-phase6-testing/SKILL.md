# PHASE 6: スルーテスト環境の構築と自動テスト実施 V2.2

- **主担当エージェント**: 🛡️ 品質・テスト & 監査・QAスペシャリスト (`qa-engineer`) (Model: `pro`)
- **委譲元 / 統括**: 👑 プロジェクトコンダクター (`conductor`)
- **知見永続化**: ⚙️ `wiki-maintainer` (RCA即時記録)
- **承認ゲート**: 👤 ユーザーによる明示的承認必須

自動テストスイートおよびシナリオテストを構築・実行し、すべてのテストがPassするまで修復ループを実行してください。

---

## 作業手順

### 1. シナリオテスト計画書の作成
- プラグインの `templates/シナリオテスト計画書.md` を `docs/plans/シナリオテスト計画書.md` に保存してください。
- `docs/` 配下の仕様（`画面仕様書.md`, `バックエンドAPI仕様書.md`, `ビジネスロジック仕様書.md`）に基づき、テストシナリオ・評価基準を完成させてください。
- **両モードテスト計画**:
  1. **モック有効モード (`VITE_ENABLE_MOCK=true`)**: MSWハンドラーによるフロントエンド独立テスト、エッジケース（4xx/5xx/遅延/オフライン）のシナリオ。
  2. **実API結合モード (`VITE_ENABLE_MOCK=false`)**: フロントエンドと実バックエンドコンテナ間の実HTTP通信シナリオ、Alembicマイグレーション適用済みDBへのデータ永続化確認。

### 2. テスト環境およびテストコードの構築
- テストフレームワーク（E2E / Integration / Unit）をセットアップし、シナリオに基づいたテストコードを作成してください。
- **DBプロビジョニング規約**:
  - テスト用データベースは必ず Alembic (`alembic upgrade head`) を通して初期化・マイグレーションを適用してください。生SQLでの手動テーブル作成は厳禁です。
- **外部API・キャッシュ検証**:
  - 外部API連携が存在する場合、ビジネスロジック仕様書に定義された二重キャッシュ（メモリLRU ＋ DB/Disk永続）が正常に機能し、2回目以降の呼び出しで外部APIアクセスが抑制されていることを検証してください。

### 3. 自動テストの実行・修復ループ・RCA即時記録 (`wiki-maintainer` 連携)
- テストを非同期・自動実行してください。
- **テスト失敗・不具合発生時の即時 RCA 記録**:
  テスト失敗や環境起因のエラーが発生した場合、`wiki-maintainer` 手順に基づき、根本原因分析 (RCA) を行い、プロジェクトローカルの `./wiki/patterns/`（Tier 1 は `local/`、Tier 2 は `universal/`）へ即時記録してください。
- **自律修復の適用範囲**:
  自律修復の対象は **「テストスクリプト」** および **「テスト環境設定」** に限定されます。
- **【重要】「システムのプログラムコード」の直接改変禁止**:
  システム本体のプログラムコードに起因する不具合・エラーを発見した場合は、**勝手にコード修正を行わず**、原因調査レポートおよびUnified Diff修正案を完了サマリに明記してコンダクターへ報告してください。コンダクターが BE/UI へ修正を委譲します。
- **コンテナ再構成の徹底**:
  テスト環境設定やコードの修復・変更を行った後は、**必ず `docker compose down` および `docker compose up --build -d` を実行して Docker コンテナをビルド・再構成**した上でテストを再実行してください。
- **反復上限**:
  修復ループの反復は **最大5回まで** とし、5回を超えてもテストが成功しない場合は処理を中断し、状況を報告してください。

### 4. 最終ドキュメント整合性レビュー (`dev-doc-reviewer`)
- テスト完了後、`dev-doc-reviewer` を実行し、修正コードとドキュメント間の整合性を最終確認・補正してください。

### 5. 標準完了サマリの返却
- テスト結果サマリをコンダクターへ返送してください。コンダクターはこれを受領して `PROJECT_STATE.md` を更新し、ユーザーへ承認ゲート確認を求めます。
