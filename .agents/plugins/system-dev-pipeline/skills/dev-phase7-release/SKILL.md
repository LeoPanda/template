# PHASE 7: 本番環境へのリリースと検証

- **主担当エージェント**: 👑 プロジェクトコンダクター (`conductor`)（手順書作成・デプロイ統括）
- **連携サブエージェント**: 🛡️ 品質・テスト & QA (`qa-engineer`)（最終不整合チェック・セキュリティ監査）
- **承認ゲート**: 👤 ユーザーによる明示的承認必須

完成したシステムを本番環境へ安全にデプロイし、本番環境のアクセス権限・セキュリティ設定を自動検証してください。

## 作業手順

1. **最終矛盾チェック（🛡️ qa-engineer 連携）**:
   - `docs/` 配下の全設計書とソースコード間の不整合・誤植・不足を最終精査してください。

2. **本番適用作業手順書の作成**:
   - プラグインの `templates/本番適用作業手順書.md` を `docs/plans/本番適用作業手順書.md` にコピー・配置してください。
   - 本プロジェクトのプロジェクトID、アプリケーションID、使用するGCPサービス、リージョンなどを確認し、手順書に反映させてください。
   - `docs/` 配下のドキュメントを走査して内容を確認した上で、不足する要素は補完し、整合性を保ちながら本プロジェクト用に最適化して完成させてください。

3. **ユーザーによる本番適用手順書の確認（承認ゲート）**:
   - 本番適用手順書をユーザーに提示し、最終確認・明示的承認を得てください。
   - 承認後、`PROJECT_STATE.md` を更新してデプロイを実行します。

4. **本番リリースの実行**:
   - `docs/plans/本番適用作業手順書.md` に従って、本番環境の構築とデプロイを実行してください。

5. **本番環境セキュリティ設定の検証（🛡️ qa-engineer 連携）**:
   - デプロイ後、インフラ設定（Cloud Run 等）のセキュリティを以下の通り自動検証・チェックリスト化してください：
     1. 認証の `IAM` および `IAP` が双方有効化されているか。
     2. Context-aware アクセスポリシー画面にて `Principal` 列に対象アクセスユーザー（メールアドレス）が正しく付与されているか。
     3. `AllUsers` アクセス権が適切に削除されているか。
   - 本番公開URLでの画面疎通テストおよび主要機能の動作検証を実施してください。

6. **状態更新と報告**:
   - 本番URL、リビジョンID、セキュリティ監査結果を `PROJECT_STATE.md` に記録し、ユーザーへ本番稼働確認の承認を要請してください。
