# PHASE 7: 本番環境へのリリースと検証

- **主担当エージェント**: 👑 プロジェクトコンダクター (`conductor`) (Model: `pro`)（デプロイ統括・専任実行）
- **システム総合レビュー担当**: 🛡️ 品質・テスト & 監査・QAスペシャリスト (`qa-engineer`) (Model: `pro`)
- **承認ゲート**: システム総合レビュー合格 (`RELEASE APPROVED`) ＋ ユーザー明示的承認必須

完成したシステムを本番環境へ安全にデプロイし、セキュリティ設定を自動検証してください。

---

## 作業手順

### 1. 本番適用作業手順書の作成
- プラグインの `templates/本番適用作業手順書.md` を `docs/plans/本番適用作業手順書.md` にコピー・配置してください。
- 本プロジェクトのプロジェクトID、アプリケーションID、使用するクラウドサービス、リージョン、コンテナ構成を手順書に反映させてください。
- **ロールバック手順の具体化**: 障害発生時の切り戻しコマンド（リビジョンロールバック、DBバックアップ復元）を必ず記載してください。

### 2. システム総合レビュー (`dev-review-system`) ゲートの通過確認
- 手順書作成後、コンダクターは 🛡️ `qa-engineer` に `dev-review-system` を委譲します。
- 🛡️ `qa-engineer` は平文シークレットゼロ、非root実行、ヘルスチェック、IAM/IAPポリシー、ロールバック手順の完全性を監査し、`docs/plans/システム総合レビュー結果報告書.md` を出力します。
- **進行前提条件**:
  - 判定が **`RELEASE APPROVED`** であることを確認してください。
  - `RELEASE BLOCKED` の場合はデプロイを即時停止し、指摘されたセキュリティ・稼働課題を解消するまで進行してはなりません。

### 3. ユーザーによる本番適用手順書の確認（承認ゲート）
- 本番適用手順書およびシステム総合レビュー結果報告書をユーザーに提示し、最終確認・明示的承認を得てください。
- 承認後、コンダクターが `PROJECT_STATE.md` を更新してデプロイを実行します。

### 4. 本番リリースの実行（コンダクター専任）
- `docs/plans/本番適用作業手順書.md` に従って、コンダクターが責任を持って本番環境へのビルド・デプロイを実行します（サブエージェントへのデプロイ委譲は禁止）。

### 5. 本番環境セキュリティ設定の検証（🛡️ qa-engineer 連携）
- デプロイ後、インフラ設定（Cloud Run 等）のセキュリティを自動検証してください：
  1. 認証の `IAM` および `IAP` が双方有効化されているか。
  2. Context-aware アクセスポリシー画面にて `Principal` 列に対象アクセスユーザー（メールアドレス）が正しく付与されているか。
  3. `AllUsers` アクセス権が適切に削除されているか。
- 本番公開URLでの画面疎通テストおよび主要機能の動作検証を実施してください。

### 6. 状態更新と報告
- 本番URL、リビジョンID、セキュリティ監査結果を `PROJECT_STATE.md` に記録し、ユーザーへ本番稼働確認の承認を要請してください。
