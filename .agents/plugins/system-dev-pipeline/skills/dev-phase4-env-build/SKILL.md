# PHASE 4: 開発環境およびシステムの構築

`docs/` 配下の設計ドキュメント一式に基づき、開発環境の構築とシステムの初版実装を行ってください。

## 作業手順

1. **仕様の確認**:
   - `docs/要件定義書.md`
   - `docs/技術要件定義書.md`
   - `docs/AI駆動ロギングシステム仕様書.md`
   - `docs/APIキー安全管理・一元化設計書.md`
   - `docs/ビジネスロジック仕様書.md`
   - `docs/画面仕様書.md`
   - `docs/テーブルスキーマ定義書.md`
   上記を精査し、不確実・不明瞭な点があれば Artifacts に質問事項を表示し確認をとってください。

2. **環境構築とシステム実装**:
   - バックエンド/フロントエンドのプロジェクト初期化、依存パッケージのインストールを行ってください。
   - 設計書通りにデータベーススキーマ、ビジネスロジック、画面/UI、API連携を実装してください。
   - **Docker Compose 設定要件**:
     `docker-compose.yml` を作成する際、開発中の不要な自動再起動ループを防止しログ解析を容易にするため、`backend` および `frontend` の両サービスにおいて `restart` オプションを `no` (`restart: "no"`) に明示的に設定してください。

3. **Dockerコンテナの生成と起動確認**:
   - **事前チェック**: Docker デーモンが正常に稼働していること、および `docker` / `docker compose` コマンドを実行可能な権限を有していることを確認してください（例: `docker info`）。
   - **コンテナ生成・起動**:
     以下のコマンドを発行して、Docker 上にコンテナをバックグラウンドでビルド・生成・起動してください。
     ```bash
     docker compose up -d --build
     ```
   - **起動状態確認**:
     コンテナ起動後、`docker compose ps` またはコンテナログ (`docker compose logs`) を確認し、`backend` および `frontend` がエラーなく正常動作していることを検証してください。
   - **【重要】修正時のDockerコンテナ再構成徹底ルール**:
     PHASE 4以降、プログラムコードや設定ファイル等のシステム修正・変更を行った場合は、ソースの変更が確実にコンポーネントに反映されるようにするため、**必ず `docker compose down` を実行した後に `docker compose up --build -d` を実行し、Docker上のコンテナをビルド・再構成する**こと。

4. **Git 管理設定**:
   - Gitリポジトリを初期化 (`git init`) し、適切な `.gitignore` を配置して初回コミットを実行してください。
