# PHASE 4: 開発環境およびシステムの構築

- **主担当エージェント**: 👑 プロジェクトコンダクター (`conductor`)（環境・Docker・BE統括）
- **連携サブエージェント**: 🎨 UI/UXデザイナー (`ui-designer`)（FE/画面コンポーネント実装）
- **Git管理**: ⚙️ `dev-git-init`

`docs/` 配下の設計ドキュメント一式に基づき、開発環境の構築とシステムの初版実装を行ってください。

## 作業手順

1. **仕様の確認**:
   - `docs/要件定義書.md`
   - `docs/技術要件定義書.md`
   - `docs/AI駆動ロギングシステム仕様書.md`
   - `docs/APIキー安全管理・一元化設計書.md`
   - `docs/ビジネスロジック仕様書.md`
   - `docs/画面仕様書.md`
   - `docs/テーブルスキーマ定義書.md`
   上記を精査し、不確実・不明瞭な点があればユーザーに確認をとってください。

2. **環境構築とシステム実装の分担**:
   - 👑 **コンダクター**:
     - バックエンドプロジェクト初期化、FastAPI等の依存パッケージインストール、データベース初期化、APIエンドポイント、ビジネスロジック実装。
     - `docker-compose.yml` を作成（`backend` および `frontend` の両サービスで `restart: "no"` を明示設定）。
   - 🎨 **UIデザイナーへの委譲**:
     - フロントエンド画面・コンポーネント実装は `invoke_subagent` で `ui-designer` に委譲し、`docs/画面仕様書.md` に沿ったUIを実装させます。

3. **Dockerコンテナの生成と起動確認**:
   - **事前チェック**: Docker デーモンが正常稼働していることを確認（`docker info`）。
   - **コンテナ生成・起動**:
     ```bash
     docker compose up -d --build
     ```
   - **起動状態確認**:
     コンテナ起動後、`docker compose ps` またはコンテナログ (`docker compose logs`) を確認し、サービスがエラーなく正常動作していることを検証。
   - **【重要】修正時のDockerコンテナ再構成徹底ルール**:
     PHASE 4以降、プログラムコードや設定ファイル等のシステム修正・変更を行った場合は、ソースの変更が確実に反映されるようにするため、**必ず `docker compose down` を実行した後に `docker compose up --build -d` を実行し、Docker上のコンテナをビルド・再構成する**こと。

4. **Git 管理設定（Git運用基準書の配置と dev-git-init の発動）**:
   - プラグインの `templates/Git運用基準書.md` をプロジェクトの `docs/Git運用基準書.md` へコピー・配置してください。
   - `dev-git-init` スキルを実行し、Gitの初期化（`main` ブランチ）、GitHubリモート設定（SSH接続）、初期ファイルの基点コミット作成、および開発用 `feature` ブランチへの切り替えを行ってください。

5. **状態更新と報告**:
   - `PROJECT_STATE.md` の PHASE 4 チェック項目を更新し、コンテナ状態とGit状態を同期した上でユーザーへ完了報告を行ってください。
