# ローカルデータベース本番上書き・デプロイスキル

本スキルは、ローカル環境の最新データベースおよびコンテナ資産を本番環境（Cloud Run等）へ反映・上書きデプロイするための自動化手順を実行します。

## 作業手順

### 1. 手順書ドキュメントの配置
- プラグイン内の `templates/AI駆動システム開発手順書_スキル活用版.md` をプロジェクトの `docs/AI駆動システム開発手順書_スキル活用版.md` にコピー・配置してください。
- 既にファイルが存在する場合は上書きまたは最新版へ更新してください。

### 2. ローカルデータベースおよび環境設定の確認
- テーブルスキーマ変更など既存データの保全を伴う場合は、本番データベースのバックアップがローカル開発環境に適用され、必要なマイグレーションおよびテストが完了していることを確認してください。
- ローカル環境のデータベースファイル（`app.db`、`data/` 配下のSQLiteファイル、ダンプファイル `app_dump.sql` 等）が最新状態であることを確認してください。
- `docs/本番適用作業手順書.md` および `docs/AI駆動システム開発手順書_スキル活用版.md` を参照し、本番デプロイに必要な環境変数、GCPプロジェクト設定（Project ID、Application ID、リージョン等）を確認してください。

### 3. 単一統合コンテナのビルドと本番デプロイ
`docs/AI駆動システム開発手順書_スキル活用版.md`（4. 本番適用後のテーブルスキーマの変更、PHASE 7 本番リリース手順）および `docs/本番適用作業手順書.md` に則り、以下の処理を実行してください：
1. **初期データ・DB配置の準備**:
   - ローカルの最新データベースファイルを本番用コンテナビルド対象（またはLitestream同期元/初期ロード対象）へ配置。
2. **本番環境・GCSバケットの準備（既存レプリケーションがある場合）**:
   - 既存のLitestreamレプリケーションデータによる旧DB復元を防ぐため、旧コンテナを停止（またはトラフィック遮断/スケールダウン）し、GCSバケット（`gs://[BUCKET_NAME]/db/`）内の旧レプリケーションデータをクリーンアップ。
3. **本番用Dockerイメージのビルド & プッシュ**:
   - 本番用Dockerfile（`Dockerfile.prod` 等）を用いて単一統合コンテナイメージをビルドし、Artifact Registryへプッシュ。
4. **Cloud Run へのデプロイ**:
   - 最大インスタンス数を1（`max-instances=1`）に設定し、本番Cloud Runサービスへデプロイを実行。
5. **Litestream / GCS データベース同期・上書きの反映**:
   - 本番環境起動時にローカルから引き継いだデータベースが正常に初期ロードされ、新たなGenerationとしてLitestreamによる同期が開始されることを確認。

### 4. 本番反映・セキュリティ検証
1. **データ反映の確認**:
   - 本番URL経由のAPI疎通や画面表示により、ローカルデータベースの内容が本番環境に正しく上書き・反映されていることを検証してください。
2. **セキュリティ設定の検証**:
   - Cloud Runの認証設定（IAM / IAP）、アクセス権限（`AllUsers`の除外、許可されたPrincipalの確認）を検証・チェックリスト化してください。

### 5. 完了報告
- デプロイ結果、本番URL、データベース反映状態、セキュリティ検証チェックリストを Artifacts にまとめ、ユーザーへ報告してください。
