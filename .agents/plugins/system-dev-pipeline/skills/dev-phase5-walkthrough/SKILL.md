# PHASE 5: ウォークスルー後ドキュメント整備と同期

- **主担当エージェント**: 👑 プロジェクトコンダクター (`conductor`)（対話ウォークスルー・修正統括）
- **連携サブエージェント**: 📐 設計・立案スペシャリスト (`architect`)（API仕様書同期）、🛡️ 品質・テスト & QA (`qa-engineer`)（整合性監査）
- **承認ゲート**: 👤 ユーザーによる明示的承認必須

ウォークスルー（動作確認）完了後のソースコードを正として、`docs/` 配下のドキュメントの作成・整備および相互整合性の補正を行ってください。

## 作業手順

1. **ユーザーによる画面操作ウォークスルー**:
   - ユーザーが画面操作や疎通検証を行い、不具合や要望を指摘します。
   - コンダクターが修正を統括し、UI修正は 🎨 `ui-designer` に委譲、BE修正はコンダクター自身が実施します。
   - **修正後のコンテナ再構成**: コード修正後は必ず `docker compose down` および `docker compose up --build -d` を実行して反映してください。

2. **ソースコード解析とバックエンドAPI仕様書の作成（📐 architect 連携）**:
   - ソースコードを解析し、以下のドキュメントを `docs/` 配下に作成・更新してください。
     - `バックエンドAPI仕様書.md`

3. **ソースコードを正としたドキュメントの不整合・不足の補正**:
   - ソースコードの最新状態を正とし、`docs/` 配下の既存ドキュメントにおける矛盾や記述不足を洗い出して修正してください。

4. **ドキュメント間不整合の確認 (`dev-doc-reviewer` / 🛡️ qa-engineer 連携)**:
   - `qa-engineer` に `dev-doc-reviewer` スキルを実行させ、`docs/` 配下のドキュメント間の不整合を確認・自律修復（最大5回ループ）させてください。

5. **状態更新と承認ゲート提示**:
   - `PROJECT_STATE.md` を更新し、ウォークスルー完了の明示的承認をユーザーに要請してください。
