# コア不変原則カタログ (Core Invariants Catalog V2.3)

本ファイルは、`system-dev-pipeline` の品質・セキュリティ・自律統制の根幹をなす **「絶対不可侵の設計原則（Core Invariants: INV-01 〜 INV-10）」** を定義する正本である。
知見フィードバック原票（`CLAIM-*.md`）の意味的整合性監査（Stage 1: Invariants Audit）において、以下のいずれかの原則を無効化・バイパス・緩和しようとする提案は、理由を問わず即座に **`REJECTED`（自動棄却）** とする。

---

## 不変原則一覧 (INV-01 〜 INV-10)

| ID | 原則名 | 絶対不可侵の制約内容（違反・弱体化は即座に `REJECTED`） |
| :--- | :--- | :--- |
| **INV-01** | **Single Writer 原則** | `PROJECT_STATE.md` の作成・更新権限は 👑 `conductor` のみが保持する。いかなるサブエージェントによる直接編集も許可してはならない。 |
| **INV-02** | **責務分離とツール実行制限** | 📐 `architect` の `run_command` 実行禁止、🛡️ `qa-engineer` のアプリ本体コード直接改変禁止、サブエージェントによる Git 操作・本番デプロイ・DB強制上書き・Docker全体起動停止の禁止を緩和してはならない。 |
| **INV-03** | **Anti-God Component / File 制限** | フロントエンド 1 コンポーネントファイル最大 250 行制限、およびバックエンド 1 モジュールファイル最大 400 行制限を撤廃・緩和してはならない。 |
| **INV-04** | **本番モックOFF・直書きモック禁止** | コンポーネント内のダミーデータ直書き禁止（MSW 集約必須）、および本番ビルド時の `VITE_ENABLE_MOCK=false` 二重防御をバイパスしてはならない。 |
| **INV-05** | **Alembic 厳格運用・生SQL禁止** | 手動 DDL（生 SQL）によるテーブル作成・変更を許可してはならない。DB スキーマ変更は必ず SQLAlchemy ORM と Alembic マイグレーションを経由させること（Profile A/B/D）。 |
| **INV-06** | **IAP JWT 署名検証・平文排除・非対話CLI保護** | 本番環境における認証検証のスキップ、シークレット・プレースホルダーの平文コミットを許容してはならない。また、外部 CLI 実行時の非対話フラグ（`--quiet` 等）強制、`2>/dev/null` による標準エラー破棄禁止、およびバックグラウンド移行タスク待機時の `schedule` タイマー保護を無効化してはならない。 |
| **INV-07** | **3大レビューゲート必須通過** | 基本設計（`dev-review-arch`）・コード品質（`dev-review-code`）・システム総合（`dev-review-system`）の3大レビューおよびスルーテスト合格なしに次フェーズへ進むバイパス経路を作ってはならない。 |
| **INV-08** | **自律修復ループの上限保護** | テスト失敗やドキュメント不整合の放置（スキップ合格化）を禁じるとともに、無限ループ防止のため自律修復ループの連続実行上限（最大 5 回）を維持する。 |
| **INV-09** | **Context Isolation とナレッジ境界** | Tier 1（案件固有仕様）を環境共通領域へ持ち出すこと、推論プロンプトへ生の Wiki 履歴を注入すること、およびルール・スキル本文（State）に履歴識別子（Lineage）を混入させることを禁じる。 |
| **INV-10** | **ドキュメント内相対パス強制** | Markdown 設計文書・仕様書内のファイルリンクに絶対パス（OS ルートからのフルパスや `file:///` スキーム等）を使用することを禁じる。必ず対象ファイル間の相対パスを使用すること。 |
