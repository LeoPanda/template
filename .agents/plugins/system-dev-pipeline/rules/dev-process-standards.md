# AI駆動システム開発プロセス標準規約 (System Dev Pipeline Rule)

本プロジェクトおよび開発パイプラインにおいては、以下の開発・運用規約に従うものとする。

## 1. ドキュメントおよびコードの文字コード・フォーマット
- すべてのドキュメントおよびソースコードは UTF-8 (BOMなし) で保存する。
- 改行コードは LF (`\n`) に統一する。
- Markdownファイルは標準記法に従い、パスの記載には `file:///` 形式のハイパーリンクを活用する。

## 2. Artifacts の活用原則
- 要件定義、技術設計の分析結果、相互矛盾点チェック結果、およびテスト計画・実行レポートは、AI Artifacts（`implementation_plan.md` や `walkthrough.md` 等）として構造化出力する。
- 不整合判定や質問事項が発生した場合は、Artifactsに明記しユーザーへ通知する。

## 3. 自律修復ループ（Self-Healing Loop）の適用と制限
- **対象範囲**:
  - 自律的な修復の対象は、**「ドキュメント」**、**「テストスクリプト」**、および**「開発環境設定・構築ファイル」**に関わるものに限定する。
  - **「システムのプログラムコード（アプリケーションのソースコード）」**に起因する不具合・エラーについては、AI自身で勝手にコード修正を行わず、原因調査結果を Artifacts に明記してユーザーの指示を仰ぐこと。
- **ループ上限回数**:
  - 自律修復ループの連続実行回数は**最大5回まで**とする。
  - 5回反復しても問題が解消されない場合は、直ちに処理を中断し、現状の分析結果とエラーログを Artifacts に詳細レポートしてユーザーの指示を仰ぐこと。


## 4. セキュリティと認証
- APIキーやシークレット情報はソースコードに直接記述せず、必ず `.env` などの環境変数で管理する。
- リリリース時には、Cloud Run / IAP / IAM の認証設定およびコンテキストアウェアアクセスポリシーが正しく設定されていることを必ず検証する。
