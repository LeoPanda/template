### 1.3 ２層構造システム展開プロファイル体系 (System Deployment Profile V2.6.2)

本システムは、以下の2層構造システムプロファイル体系に基づき設計・構築されます。

#### 【第1層: 定常的コア設計規範 (Universal Core Specifications)】
いかなる規模・プロファイルであっても、技術的負債化を防止するために無条件で初期配置・遵守する普遍的規範：
1. **フロント/バック責務分離構造 & Hard Gate 物理遮断**: フロントエンド1ファイル最大250行制限、バックエンド1ファイル最大400行制限、ASTレイヤーバイパス禁止。
2. **要件トレーサビリティ & 3階層深層アサーション**: `REQ-*` カバレッジ 100%、異常系テスト比率 20% 以上、自己完結型トートロジー・テスト排除。
3. **ブラウザ感覚センサー**: 実ブラウザのコンソールエラー 0 件、WCAG AA コントラスト比（4.5:1）、A11yツリー自動検証。
4. **型定義自動同期パイプライン**: OpenAPI (FastAPI) スキーマから TypeScript 型定義を自動生成 (`npm run codegen:types`)。
5. **シークレット厳格バリデーション & Dual Provisioning 原則**: Pydantic Settings による起動時即死ガード、`.env.example` と `.env` の常時同期・自動補完。
6. **統一タイムゾーン運用**: DB保存およびAPI通信は Aware UTC (ISO8601)、UI表示時のみ JST へ変換。
7. **モック制御アダプター層 (Fail-Fast原則)**: 環境変数 `VITE_ENABLE_MOCK=true/false` による明示的切替 (案C) とコンポーネント内直書きモック排除 (案A)。実結合モードでのサイレントモックフォールバック厳格禁止。
8. **画面グランドデザイン規範 & デイライト視認性**: 4px/8px グリッド体系、HEX/px絶対値併記、ウィンドウ形態選定基準の遵守。デイライトモード視認性担保のためTailwind明暗ペア指定またはセマンティックトークンを必須化。
9. **CI・静的解析・テスト実行ディレクトリ非依存**: GitHub Actions 自動検証、リント循環参照許容、実行カレントディレクトリ非依存パス解決。

#### 【第2層: 可変的システム展開プロファイル (Deployment Profiles)】
システムの稼働環境・規模・要件に基づき、以下のディシジョンツリーにより選定します。

- **選定プロファイル**: **[Profile A / Profile B / Profile C / Profile D / Profile E]**

| プロファイル | ターゲット・用途 | 標準技術スタック | 選定理由・特徴 |
| :--- | :--- | :--- | :--- |
| **Profile A (サーバーレス極小コストWeb型 / ゴールデンパス)** | 個人開発、小規模SaaS、社内Webツール、月額数十円〜無料枠運用 | Google Cloud Run (max-instances=1) + Litestream + SQLite (WAL) + Alembic + FastAPI + React SPA + Tailwind CSS + MSW | 極小インフラコストと高可用性・耐障害性・IAP二重防御の両立 |
| **Profile B (Web SSR / フルマネージドRDB型)** | 中〜大規模Webサービス、SEO必須サイト、高頻度トランザクション | Next.js / Nuxt 3 (SSR/Islands) または FastAPI + Cloud SQL (PostgreSQL) + Alembic | 水平オートスケール、完全なRDBトランザクション |
| **Profile C (静的MPA / 超軽量ツール型)** | 社内ユーティリティ、単一バイナリ配布ツール、管理画面 | FastAPI / Go + Jinja2/html-template + HTMX + SQLite (単一プロセス) | ビルドパイプライン最小化、単一プロセス完結 |
| **Profile D (PCローカルデスクトップアプリ型)** | オフライン作業ツール、ローカルファイル直接処理、OSネイティブUI | Tauri v2 (Rust + React) / Electron / PyQt + Local SQLite (WAL) + Frameless TitleBar | OSネイティブ機能活用、ローカル完結、セキュアストレージ、二段階ハイブリッド運用 |
| **Profile E (AI Agent Skill / PKM 自動化・CLI型)** | AI Agentスキル、PKM自動化スクリプト、単一バイナリCLI | Zero-Dependency Python 3 (標準ライブラリのみ) + アトミックI/O + 2系統分離設計 | 決定論的Hard GateスクリプトとSoft Engineプロンプト分離、テストコード必須 |

#### プロファイル選定ディシジョンツリー & 5大適合性診断
1. **端末・ファイル親和性**: ローカルファイル直接処理やオフライン利用が主目的か？ ➔ **Yes: Profile D**
2. **配布・スクリプト形態**: 単一Pythonファイルで完結する自動化スキル・CLIか？ ➔ **Yes: Profile E**
3. **UI/UXリッチネス・ビルドレス運用**: 単一プロセス・ビルドレスMPA（HTMX等）が最優先か？ ➔ **Yes: Profile C**
4. **規模・トランザクション頻度**: 高頻度同時書き込み（複数インスタンス）やSEO必須の大規模サービスか？ ➔ **Yes: Profile B**
5. **インフラ運用コスト**: 個人〜小規模SaaS、極小コスト（無料枠〜数十円）、単一ライター保護で十分か？ ➔ **Yes: Profile A (最優先ゴールデンパス)**

## 2. システムの機能要件 (Functional Requirements)

各機能要件にはトレーサビリティ検証用の固有ID `[REQ-Fxx]` およびサブ要件ID `[REQ-Fxx-yy]` を付与し、設計書・テストコードと1対1で対応付けます。

### 2.1 [REQ-F01] ダッシュボード機能
- **[REQ-F01-01] 主要メトリクスサマリー表示**: システム主要データの総件数、カテゴリ別内訳、直近推移をサマリーカード形式でリアルタイム表示。
- **[REQ-F01-02] 注意喚起インジケーター**: 一定期間更新のないエンティティに対し、視覚的なアラートドット（Pulse Rose `#e11d48`）を動的描画。

### 2.2 [REQ-F02] リアルタイム横断検索機能
- **[REQ-F02-01] インクリメンタル絞り込み**: 入力キーワード（名称、コード、概要等）に基づき、300ms以内のデバウンスで一覧データを即時絞り込み。
- **[REQ-F02-02] 複合フィルター**: カテゴリ、ステータス、期間によるAND条件での複合絞り込み。

### 2.3 [REQ-F03] マスタ管理機能
- **[REQ-F03-01] マスタCRUD操作**: 各種区分・分類マスタの登録、一覧表示、編集、削除。
- **[REQ-F03-02] 参照整合性保護**: 既存エンティティから参照されているマスタの削除を遮断（409 Conflict）。

### 2.4 [REQ-F04] 一覧・詳細画面機能
- **[REQ-F04-01] ハイブリッド表示切替**: デスクトップ表示（テーブル形式）とモバイル表示（カード型グリッド）の自動レスポンシブ変形。
- **[REQ-F04-02] インライン・モーダル編集**: 簡易項目はインライン編集、複合エンティティは標準モーダルまたはスライドインドロワーで編集。

### 2.5 [REQ-F05] 外部システム・API連携 & 二重キャッシュ機能
- **[REQ-F05-01] TTLメモリキャッシュ**: 外部APIレスポンスを高頻度（TTL 60秒〜10分）でインメモリ保持。
- **[REQ-F05-02] SQLiteテーブルキャッシュ**: 障害時フォールバックおよびコールドスタート高速化のためのDB永続キャッシュ（TTL 5分〜24時間）。

## 3. 非機能要件・セキュリティ・品質 (Non-Functional Requirements)

### 3.1 定常的コア非機能要件（全プロファイル共通）

#### [REQ-NF01] フロント/バック責務分離構造 & Hard Gate 物理遮断
- フロントエンド1ファイル最大250行制限、バックエンド1ファイル最大400行制限。
- DTO分離（`schemas/`）、レイヤーバイパス禁止（routersからmodels直接import禁止）、例外握りつぶし禁止（`except: pass` 排除）。
- コミット前 Git `pre-commit` および CI ゲートで `harness_guard.py` により機械遮断。

#### [REQ-NF02] 要件トレーサビリティ & 3階層深層アサーション
- 要件定義 `REQ-*` から設計・テストコードまでの 100% カバレッジを維持。
- 異常系テスト比率 20% 以上を機械検証。
- 単なるDOM存在確認や自己完結型トートロジー・テスト（`assert True`、定数比較等）を排除し、構造・状態遷移・副作用の3階層深層アサーションを検証。

#### [REQ-NF03] ブラウザ感覚センサー検証
- 実ブラウザにおいてコンソールエラー 0 件。
- WCAG AA コントラスト比（4.5:1）および A11y ツリー適合を自動検証。

#### [REQ-NF04] 型定義自動同期パイプライン
- OpenAPI スキーマから TypeScript 型定義を完全自動生成し、手動型定義の二重管理を排除。

#### [REQ-NF05] シークレット厳格バリデーション & Dual Provisioning
- Pydantic Settings による起動時即死ガード。
- `.env.example`（公開テンプレート）と `.env`（ローカル実体）の常時同期および未設定時自己修復。

#### [REQ-NF06] 統一タイムゾーン運用
- DB保存およびAPI送受信は Aware UTC（ISO8601）、UI表示時のみ JST へ変換。

#### [REQ-NF07] モック制御アダプター層 (Fail-Fast原則)
- 環境変数切替（案C: `VITE_ENABLE_MOCK=true/false`）と直書きモック排除（案A: `src/mocks/` 集約）。
- 実結合モードでのサイレントモックフォールバック厳格禁止。

#### [REQ-NF08] 画面グランドデザイン規範 & デイライト視認性
- 4px/8px グリッド体系、HEX/px絶対値併記、ウィンドウ形態選定基準の遵守。
- Tailwind 明暗ペア指定（`bg-white dark:bg-slate-900 text-slate-900 dark:text-slate-100` 等）によるデイライト視認性の完全担保。

#### [REQ-NF09] CI・静的解析・テスト実行ディレクトリ非依存
- GitHub Actions 自動検証パイプライン。
- 静的解析におけるフレームワーク標準イディオム（FastAPI `Depends` 等）の競合抑止および循環参照許容。
- テストコードの実行カレントディレクトリ非依存パス解決。

### 3.2 システム展開プロファイル別非機能要件

#### [REQ-NF10] 認証・認可およびアクセス制御
- **Profile A 選定時**: Google Cloud Run の Identity-Aware Proxy (IAP) 前段認証に加え、FastAPIバックエンド層（`core/auth.py`）において `X-Goog-IAP-JWT-Assertion` トークンの公開鍵署名検証を二重防御として必須実装（開発環境 `DEBUG=True` 時のみ安全なローカルモックへ自動フォールバック）。
- **Profile D 選定時**: OSセキュアストレージ / キーチェーンを活用した資格情報保護。

#### [REQ-NF11] データベース永続化・マイグレーション・バックアップ構成
- **Profile A 選定時**:
  - SQLite WALモード (`PRAGMA journal_mode=WAL;`, `PRAGMA busy_timeout=5000;`, `PRAGMA foreign_keys=ON;`)
  - Alembic マイグレーション厳格運用（生SQL手動DDL完全排除）
  - Litestream レプリケーション（起動時リストア＋GCS継続非同期レプリケーション、正規スーパーバイザー起動構文 `exec litestream replicate -config ... -exec "uvicorn ..."` 遵守）
  - Cloud Run `max-instances=1` (SQLite 単一ライター制約保護)
- **Profile D 選定時**: Local SQLite WALモード ＋ Alembic マイグレーション。

#### [REQ-NF12] 内部監視・可観測性
- 死活監視エンドポイント (`GET /api/internal/health`)
- Litestream同期ラグ監視エンドポイント (`GET /api/internal/litestream/status`)

#### [REQ-NF13] クライアントネイティブ・ハイブリッド実行環境 (Profile D)
- Tauri v2 二段階ハイブリッド運用（PHASE 4〜5: ブラウザモード、PHASE 6: 実機ネイティブ）。
- Frameless TitleBar、システムトレイ、ローカルファイルセキュアI/O。

## 4. UI/UX・グランドデザイン標準仕様

### 4.1 デザイントークン & レイアウト規格
- **グランドデザイン全面準拠**: [01_グランドデザイン基本仕様書.md](./グランドデザイン/01_グランドデザイン基本仕様書.md) に規定されたセマンティックカラー（Blue `#2563eb`, Slate `#0f172a`, Emerald `#059669`, Rose `#e11d48` 等）および 4px/8px グリッドを厳格適用。
- **メインコンテナ**: デスクトップ表示時 `max-w-[1800px] mx-auto`。
- **ウィンドウ形態選定基準**: 簡易確認・マスタ追加は「標準モーダル」、複合編集は「スライドインドロワー」、デスクトップ時は「スプリットペイン / Frameless TitleBar」を採用。

### 4.2 テーマ切り替え機能（マルチテーマ）
- 「ライトモード」「ダークモード」「システム (OS設定追従)」の 3 つの表示モード切替をサポート。

### 4.3 ボタン類のミニマルアイコン化および英語Tooltip表記ルール
- 操作ボタン（Edit, Delete, Search, Sync 等）はアイコンのみのミニマル表示とし、英語表記（Title Case）のツールチップ (`title`) を付与。

### 4.4 画像最適化仕様
- 画像アップロード時はブラウザ側 Canvas API により **700px × 700px 正方形 WebP (80%品質)** に事前圧縮して送信。
