## 1. はじめに

### 1.1 目的と背景
AI駆動システム開発テンプレートは、V2.0 における協調体制・ガードレール確立、V2.1 における3大レビューシステム・WikiSkill型自己進化ループ・定量測定機構、V2.2 における Shift-Left（2層プロファイル体系・静的スケルトン・モック制御・グランドデザイン）を経て高度に体系化された。

さらに V2.3 においては、複数プロジェクト・複数環境での自己進化運用において発生した「パッチ競合」「新バージョン更新時のローカル知見消失」「ルール間の意味的矛盾」「履歴ID追記によるプロンプト肥大化」「PHASE 8 検証ゲートの形骸化」を抜本的に解決するため、[V2.3新知見フィードバック機構設計書.md](./V2.3新知見フィードバック機構設計書.md) に基づき、サブエージェント体系、スキル群、ガバナンス台帳、および Central Knowledge Hub 連携スクリプトを再構成する。

### 1.2 本計画書のスコープ
1. **エージェント体制の行動規範再定義**: 2層プロファイル適応・Shift-Left に加え、Knowledge Hub 連携、3段階意味的整合性監査（Semantic Auditor）、履歴ノイズゼロ・絶対行数バジェット（120行以内）の徹底。
2. **Immutable Core ＋ Local Overlay 二層プラグイン資産の設計**: `CORE_INVARIANTS.md`、`PIPELINE_MANIFEST.json`、`FEEDBACK_LEDGER.md`、`scripts/pipeline-reconciler.sh` の新設と、個別 `PURPOSE.md` の廃止統合。
3. **スキル群の再構成設計**: `.patch` 出力を廃止し、標準化知見原票（`CLAIM-*.md`）投函・3段階監査・`LOCAL_FEEDBACK_RULES.md` クリーン再生成へ刷新。
4. **テンプレートおよびルールの再構成設計**: `rules/AGENTS.md`（上限220行・Local Overlay 動的参照フック搭載）および `PROJECT_STATE.md.template` / `TEMPLATE_PROMOTIONS.md.template` の V2.3 更新。

## 5. テンプレート雛形およびガバナンスファイルの再構成設計

1. **`rules/CORE_INVARIANTS.md`（新規）**: Single Writer（INV-01）、ツール制限（INV-02）、250行/400行制限（INV-03）、直書きモック禁止・本番モックOFF（INV-04）、Alembic厳格運用・生SQL禁止（INV-05）、IAP JWT検証・平文排除（INV-06）、3大レビュー必須通過（INV-07）、自律修復5回上限（INV-08）、Context Isolation・Tier 1 閉塞（INV-09）、相対パス強制（INV-10）の10大不変原則を定義。
2. **`PIPELINE_MANIFEST.json` & `FEEDBACK_LEDGER.md`（新規）**: プラグインルートに配置し、個別 `skills/*/PURPOSE.md` を廃止して系譜管理を一元化。
3. **`templates/PROJECT_STATE.md.template`（V2.3改訂）**: `BASE_CORE_VERSION`, `KNOWLEDGE_HUB_PATH`, PHASE 1 Hub 未処理検知、PHASE 8 原票投函・3段階監査・Overlay 再生成チェック項目を反映。
4. **`templates/TEMPLATE_PROMOTIONS.md.template`（V2.3改訂）**: `.patch` 案内を廃止し、標準化知見原票（`CLAIM-*.md`）および 3段階意味的監査結果・Overlay 反映ステータスの提示フォーマットへ刷新。
