## 1. 目的と位置付け

本ドキュメントは、AI駆動システム開発ライフサイクル V2.3 における「Shift-Left（品質・標準の前倒し組み込み）」「2層構造システムプロファイル体系」「静的スケルトン層（`skeletons/`）」「モックアップ制御（案C＋案A）」「画面グランドデザイン」に加え、V2.3 で導入された **「Central Knowledge Hub（`~/.gemini/knowledge-hub/`）」「標準化知見原票（`CLAIM-*.md`）」「3段階意味的整合性監査（`CORE_INVARIANTS.md` ＆ 4分類矛盾処置）」「Immutable Core ＋ Local Overlay 二層構成」「State と Lineage の完全分離（履歴ノイズ排除＆絶対行数バジェット）」** を、プラグイン構成ファイル群（`.agents/plugins/system-dev-pipeline/`）およびテンプレート資産に反映・再編集する際に徹底すべき12大配慮事項をまとめた技術仕様書である。

### 配慮事項 1: スキルの実行主体（Who）と委譲・完了サマリフローの整合性再定義
- 全スキルの冒頭に主担当エージェントを明記し、サブエージェント完了時はコンダクターへ標準完了サマリ（獲得知見含む）を返却させる。
- 実行主体のマッピング:
  - `dev-phase1-setup`, `dev-phase7-release`, `dev-phase8-rules`, `wiki-proposer`, `wiki-compactor`, `dev-metrics-collector`, `dev-git-*`, `dev-db-overwrite`: 👑 コンダクター主担当。
  - `dev-phase2-requirements`, `dev-phase3-design`: 📐 `architect` 主担当。
  - `dev-phase4-env-build`: 👑 コンダクター (統括) ＋ 💻 `backend-engineer` (BE/Alembic) ＋ 🎨 `ui-designer` (FE/MSW) 並行分担。
  - `dev-phase5-walkthrough`: 👑 コンダクター (対話統括) ＋ 📐 `architect` (API仕様同期) ＋ 💻 BE / 🎨 UI (修正)。
  - `dev-review-arch`, `dev-review-code`, `dev-review-system`, `dev-phase6-testing`, `dev-doc-reviewer`, `wiki-maintainer`, および PHASE 8 の **Semantic Auditor（3段階意味的整合性監査）**: 🛡️ `qa-engineer` 主担当。

---

### 配慮事項 2: プラグイン仕様に基づくエージェント定義と動的ロード保証
- `plugin.json` への `"agents": ["conductor", "architect", "backend-engineer", "ui-designer", "qa-engineer"]` の正規記述。
- メインエージェント（コンダクター）の初期動作ルールに、動的定義フォールバック（`define_subagent`）を明記。

---

### 配慮事項 3: ツール・コマンド権限の厳格な分離と非対話CLI・タイムアウト保護（INV-02）
- 📐 `architect`: `run_command` 禁止の推論レベルブロック。
- 破壊的操作のコンダクター専任化（Git操作、デプロイ、DB強制上書き、コンテナ全体起動停止）。
- 💻 `backend-engineer`: バックエンド構文チェック・単体テスト、コンテナ内コマンド実行に限定。生SQL禁止（INV-05）。
- 🎨 `ui-designer`: パッケージ導入、ローカルUIビルドに限定。
- 🛡️ `qa-engineer`: テスト・リンター・行数計測等に限定。アプリコード直接改変の禁止。
- **外部CLIの非対話実行とタイムアウト保護**: `gcloud`, `npm`, `patch` 等の実行時は確認プロンプト待ちハングを防ぐため `--quiet`, `--yes`, `-N` 等の非対話オプションを強制し、バックグラウンド移行タスク待機時は `schedule` タイマー（`DurationSeconds=60`, `TimerCondition="<task-id>"`）を併用する。

---

### 配慮事項 4: PROJECT_STATE.md の Single Writer 原則と Knowledge Hub 連携追跡（INV-01）
- `PROJECT_STATE.md` への書き込み権限を持つのは **👑 コンダクターのみ**。
- 2層プロファイル選定結果、モック動作モード（`MOCK_MODE`）、3大レビューゲート合否に加え、ベースとしている Immutable Core バージョン（`BASE_CORE_VERSION`）および PHASE 8 での知見原票投函・Overlay 反映ステータスを一元記録する。

---

### 配慮事項 5: テンプレート雛形とルールファイル（`rules/AGENTS.md`, `CORE_INVARIANTS.md`）のクロスリファレンス整合性
- `rules/CORE_INVARIANTS.md` に絶対不可侵の10原則（INV-01〜INV-10）を明文化し、フィードバック監査の第一関門とする。
- `rules/AGENTS.md` の末尾に「`~/.gemini/knowledge-hub/overlay/LOCAL_FEEDBACK_RULES.md` が存在する場合は追加の環境オーバーレイ規約として併せて遵守すること」という動的参照フックを搭載する。

---

### 配慮事項 6: Immutable Core ＋ Local Overlay 分離と Upgrade Reconciler による安全な更新（3-A / 3-B）
- 個別アプリケーション開発案件の PHASE 8 において、`~/.gemini/config/plugins/system-dev-pipeline/`（Immutable Core）のファイルを直接書き換えてはならない。また `.patch` ファイルの生成も全面廃止する。
- PHASE 8 で監査・承認された Tier 2 知見は、すべて `~/.gemini/knowledge-hub/active_claims/` に原票保管し、`overlay/LOCAL_FEEDBACK_RULES.md` をクリーン再生成して反映する。
- 新バージョンの Core 配布時は `scripts/pipeline-reconciler.sh --upgrade` を実行し、`PIPELINE_MANIFEST.json` との4分類照合（ID一致自動退役 / 意味的重複の対話承認 / 独自知見保持 / 仕様衝突保留）を行う。

---

### 配慮事項 7: Context Isolation と State/Lineage 完全分離（1-C / 3-C）
- 通常の開発推論エージェントには、`./wiki/patterns/`、生ログ、および `FEEDBACK_LEDGER.md` を一切見せない。
- **`rules/AGENTS.md`, `agents/*.md`, `skills/*/SKILL.md`, `LOCAL_FEEDBACK_RULES.md` の本文（State）には、`[PAT-SYS-001]` や `[CLAIM-...]` 等の履歴ID・障害経緯（Lineage）を1文字たりとも記述してはならない**。
- 各スキルディレクトリ直下の `PURPOSE.md` は廃止し、適合履歴と動機はプラグインルートの `FEEDBACK_LEDGER.md` および `PIPELINE_MANIFEST.json` へ完全一元化する。

---

### 配慮事項 8: ドキュメント内相対リンク強制（INV-10）とパーサー誤認防止ファイル命名規約
- 全ドキュメント内の内部リンクは、環境非依存性を担保するため、すべて対象ファイル間の**相対パス**を使用する（絶対パス禁止）。

---

### 配慮事項 9: 静的スケルトン（`skeletons/`）と可変ドメイン生成のハイブリッド境界の遵守
- 基盤コード（Alembicマイグレーション環境、`entrypoint.sh`、CIワークフロー、SQLiteセッション基盤、IAP JWT署名検証ミドルウェア、共通フック、MSWモック基盤）は、`skeletons/` から静的に初期展開する。

---

### 配慮事項 10: 外部システム・APIモックアップ制御（案C＋案A）と本番漏洩防止二重防御（INV-04）
- `.env` の `VITE_ENABLE_MOCK=true/false` によりモック（MSW等）と実API通信を透過的に切り替え、コンポーネント内の直書きモックを禁止する。PHASE 5.5 と PHASE 7 で二重監査する。

---

### 配慮事項 11: 絶対行数バジェット（Hard Line Budget）の厳守とインプレース蒸留（2-B）
- コンテキスト肥大化を防ぐため、以下の絶対行数上限（Hard Line Budget）を機械的に強制する：
  - `rules/AGENTS.md`: **最大 220 行**
  - `agents/*.md`: **最大 120 行**
  - `skills/*/SKILL.md`: **最大 120 行**
  - `overlay/LOCAL_FEEDBACK_RULES.md`: **最大 80 行**
- 新しい知見を統合する際は、末尾への単純追記（Append）を禁止し、既存箇条書きへのインプレース統合（`SUBSUMPTION`）または詳細処理の `scripts/` 外出しによって行数バジェット内に収める。

---

### 配慮事項 12: テンプレート改訂時の Global ⇔ Workspace 正本同期ガードレールの遵守
- 本 `template` ワークスペースでパイプライン構成資産を改訂する際は、[パイプラインの改訂時におけるグローバルとワークスペースの同期について.md](./パイプラインの改訂時におけるグローバルとワークスペースの同期について.md) に従い、「① 新規改訂開始前」および「② ワークスペースのソース改変前」に必ず `template-pipeline-sync` スキルを実行し、Global 環境および `~/.gemini/knowledge-hub/` とのドリフトを解消し `.git/pipeline_sync_stamp` を更新する。
