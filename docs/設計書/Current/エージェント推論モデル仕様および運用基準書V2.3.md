## 1. 背景と目的

Antigravityマルチエージェント開発環境において、各エージェント（メインエージェントおよびサブエージェント）に割り当てる推論モデル（`Model`）の仕様、論理ティア（抽象階層）の仕組み、および今後のGeminiバージョンアップ時における保守・運用方針について定義するものである。

V2.3においては、V2.2の **Shift-Left（品質・標準の前倒し組み込み）**、**2層プロファイル体系（定常コア8項目＋Profile A〜D）**、**Anti-God Component（1ファイル最大250行制限）** に加え、**Central Knowledge Hub（`~/.gemini/knowledge-hub/`）を用いた知見原票（`CLAIM-*.md`）の3段階意味的整合性監査（Semantic Conflict Audit）およびインプレース統合圧縮（Synthesize）** が導入されたため、各エージェントの推論負荷とタスク特性に応じた最適なモデル割り当て基準を定義する。

---

## 2. モデル指定子のアーキテクチャ（論理ティア設計）

Antigravity のエージェントランタイム（`invoke_subagent` 等）における `Model` パラメータは、特定の具体的なモデルバージョン文字列（例: `gemini-3.8-flash` 等）を直接指定する方式ではなく、**役割や計算リソースに応じた「抽象化されたモデル階層（論理ティア）」** として設計されている。

### サポートされているモデル指定子一覧 (`invoke_subagent` 引数)

| 指定値 (`Model`) | 役割と対象タスク | 想定されるモデル特性 | 推奨用途 |
| :--- | :--- | :--- | :--- |
| **`inherit`**<br>(デフォルト) | 呼び出し元（親エージェント）のモデル設定をそのまま継承 | 親エージェントと完全に同一のモデルで実行 | 基本的なデフォルト指定 |
| **`flash_lite`** | 非常に軽量な単純タスク | 最小コスト・超高速 | 単純なテキスト変換・フラグ判定など |
| **`flash`** | 軽量・高速な探索・閲覧・試行錯誤タスク | 高速・低レイテンシ | ファイル閲覧、キーワード検索、一次リサーチ、UIレイアウト試行錯誤 |
| **`pro`** | **深い推論（Deep Reasoning）、高度な設計、大規模リファクタリング、多段階計画、厳格な意味的監査** | **最上位推論・高キャパシティ** | 2層プロファイル設計、Alembic/BE実装、3大レビュー、250行制限・モック排除監査、PHASE 8 3段階意味的整合性監査（新複合検証ゲート） |

---

## 3. 「Proモデル」の具体的位置づけと実体

### 3.1 プラットフォーム側での動的ルーティング
ユーザーがUI上でベースモデルとして例えば「Gemini 3.8 Flash」を選択している場合であっても、サブエージェント呼び出し時に `Model: "pro"` を明示すると、以下のように動作する：

```
[親エージェント: Conductor] ──── (invoke_subagent: Model="pro") ────> [サブエージェント: Architect / QA / BE]
      │                                                                           │
      ▼                                                                           ▼
  Flash系推論エンジン                                                         Pro系推論エンジン
 (通常対話・オーケストレーション)                                             (深い推論・設計・レビュー・意味的監査・BE実装)
```

* **実体**: Google / Antigravity のバックエンドインフラ側において、**「その時点で利用可能な最高性能の推論モデル（Proクラス / Reasoning強化モデル）」** に自動的にバインド（ルーティング）される論理エイリアスである。
* **狙い**: 普段のチャットや全体統括はレスポンスが高速なFlash系を使いつつ、高い論理的思考力が要求される専門エージェントにのみPro系の推論リソースを局所的に割り振ることで、全体の処理速度と推論精度の最適化を両立する。

---

## 4. Geminiバージョンアップ時の保守方針（変更不要性）

Geminiの世代が新しくなった場合でも、**設計書やエージェント呼び出しコードを都度書き換える必要はない**。
論理ティア名（`pro`, `flash`, `inherit`）を使用しているため、プラットフォーム側で新しい安定版がロールアウトされると自動的に最新ターゲットへ更新される。

## 5. 各エージェントにおけるモデル割り当て基準 (V2.3)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       エージェント別 モデル割り当て指針 (V2.3)              │
├────────────────────────────────┬───────────────┬────────────────────────────┤
│ エージェント名 / 役割          │ 指定モデル    │ 選定理由                   │
├────────────────────────────────┼───────────────┼────────────────────────────┤
│ 👑 conductor (コンダクター)    │ inherit / pro │ 進行管理・Hubオーケストレーション│
│ 📐 architect (設計スペシャリスト)│ pro           │ 2層プロファイル・多次元整合│
│ 💻 backend-engineer (BE実装)   │ pro           │ Alembic/IAP/キャッシュ実装│
│ 🎨 ui-designer (UI/UXデザイナー)│ flash または pro│ 250行制限/MSW/グランドデザイン│
│ 🛡️ qa-engineer (QA・監査・検証)│ pro           │ 3大レビュー・3段階意味的監査│
│ 🔍 research (リサーチ)          │ flash         │ 高速探索・情報収集         │
└────────────────────────────────┴───────────────┴────────────────────────────┘
```

1. **📐 architect (`pro`)**
   - 2層構造プロファイル体系（定常コア8項目＋Profile A〜D）の選定・設計、外部API二重キャッシュ、モック制御仕様の設計など、文脈把握と論理矛盾の検証に極めて高度な推論を要するため。
2. **💻 backend-engineer (`pro`)**
   - 生SQL手動DDLを排除したSQLAlchemyモデル定義、Alembicマイグレーションの自動生成・整合性維持、IAP JWT署名検証ミドルウェア、内部監視エンドポイントの実装など、堅牢なシステム基盤構築にProティアの深い論理推論が不可欠であるため。
3. **🛡️ qa-engineer (`pro`)**
   - **2層構造 3大レビュー（基本設計レビュー、コード品質レビュー、システム総合レビュー）** の批判的検証（Red Team的アプローチ）、**1ファイル最大250行制限の機械的監査**、**直書きモック残留検査**、**本番モックOFF・IAP検証確認**、E2Eシナリオテスト自動生成に加え、V2.3で導入された **3段階の意味的整合性監査（Semantic Auditor：不変原則照合・4分類相互矛盾判定・コンテキスト純度＆行数バジェット内でのインプレース統合圧縮）** を担うため、最上位の推論力が必要。
4. **🎨 ui-designer (`flash` または `pro`)**
   - グランドデザイン新規格（4px/8pxグリッド、HEX/px絶対値併記）に準拠した画面仕様書の作成、**Anti-God Component（1ファイル最大250行制限）に基づくコンポーネント分割**、MSWモックハンドラー構築など、構造的設計・リファクタリング時は `pro` を推奨。
   - 初期のUIレイアウト試行錯誤やCSS微調整は高速な `flash` を推奨。
5. **👑 conductor (`inherit` または `pro`)**
   - 通常の対話進行や状態管理（Single Writer）、スケルトン展開、標準コマンドシーケンス実行は高速なベースモデル（`inherit`）で対応可能。大規模な文脈要約、Knowledge Hub の原票起案（`wiki-proposer`）、および `LOCAL_FEEDBACK_RULES.md` クリーン再生成・Upstream Merge 時は `pro` を指定可。
6. **🔍 research (`flash`)**
   - ソースコード検索やWeb上の公式ドキュメント調査など、レイテンシと探索スピードが重視されるタスクに最適。

## 6. まとめ・運用ルール

* **新エージェント作成時**:
  * 具体的バージョン番号（`gemini-X.Y-...`）は一切記載せず、必ず `inherit`, `pro`, `flash`, `flash_lite` のいずれかを使用すること。
* **モデル指定の引数解決ルール**:
  * モデルの割り当てはエージェント静的定義（YAML Frontmatterの `default_model`）に閉じ込めるのではなく、親エージェント（コンダクター）が `invoke_subagent` を呼び出す際の引数（`Model`）で明示的に制御する。
  * コンダクターが明示的に指定しない場合、Frontmatterの `default_model` を読み取って引数へセットし、Antigravity既定値への意図しないフォールバックを防止する。
