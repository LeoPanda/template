## 1. 採択された基本方針 (V3.0.0 決定事項)

AI駆動システム開発ライフサイクル V3.0.0 におけるエージェント設計の基本方針は以下の通りである。

| 検討項目 | 採択方針 | 詳細内容 |
| :--- | :--- | :--- |
| **1. 開発思想** | **Executable Contract ＆ 2段階緩衝帯** | 事後レビューだけでなく、実行可能な契約（Golden Fixtures、Stage 1.5 スモーク）と2段階行数制限（FE 250/350行、BE 400/550行）、空実装遮断（`HG-010`）で実動品質を担保する。 |
| **2. プロファイル適応** | **2.5層プロファイル体系 (Core ＋ Traits)** | 📐 `architect` が第1層（定常コア）、第2層（Core Profile A〜E）、および Capability Traits（`+trait:*`）を設計し、全要件に `[REQ-*]` を採番する。 |
| **3. フロントエンド規約** | **Anti-God Component ＆ Contract-First MSW** | 🎨 `ui-designer` が 2段階行数制限・空ハンドラ禁止を遵守し、`openapi.json` 生成型拘束MSW、動的描画 O(1) キャッシュ、実ブラウザ感覚センサー検証に対応する。 |
| **4. バックエンド規約** | **Stage 1.5 スモーク ＆ 2段階行数ガード** | 💻 `backend-engineer` が 2段階行数制限、空実装遮断、DTO分離、生SQL排除、および `TestClient` によるインプロセス実I/Oスモークテストを義務付ける。 |
| **5. 統括・状態管理** | **Hybrid State Ledger ＆ 自律昇格** | 👑 `conductor` が `state_manager.py` により台帳を更新。非開発モード時のパス監視と `start-revision` 自律昇格、および `REV-4` 実機レビュー要請・改修統括を担当する。 |
| **6. レビュー・監査統制** | **Active QA ＆ qa_runtime_evidence** | 🛡️ `qa-engineer` が検証プローブを永続化し、テスト関数直結 RTM 検証、Stage 2 実結合E2E、および `metrics/qa_runtime_evidence.json` の発行・検証を行う。 |
| **7. 知見フィードバック** | **Central Knowledge Hub ＆ 3段階意味的監査** | 👑 `conductor` が知見原票を投函し、🛡️ `qa-engineer`（Semantic Auditor）が監査、承認後に Local Overlay をクリーン再生成する。 |

## 4. エージェント別プロンプト定義と振る舞い規範 (V2.5)

### 4.1 👑 プロジェクトコンダクター (`conductor`)
- **Single Writer 原則の厳守**: `PROJECT_STATE.md` を更新できる唯一の存在として進行管理を行う。
- **メトリクス集計後の即時反映同期 (PAT-SYS-002)**: `dev-metrics-collector` 実行後、主要数値を `PROJECT_STATE.md` の定量サマリへ即時反映し、ヘッダー更新日時を更新する。
- **Central Knowledge Hub パターンID一意性管理 (PAT-SYS-006)**: `wiki-proposer` 実行時に全環境で未使用の最新連番を採番する。

### 4.2 📐 設計・立案スペシャリスト (`architect`)
- **2層プロファイル体系の設計義務化**: 要件定義時にディシジョンツリーを適用してプロファイルを確定する。
- **【絶対禁止】いかなる場合も `run_command` を呼び出してはならない。**

### 4.3 💻 バックエンドエンジニア (`backend-engineer`)
- **生SQL手動DDLの絶対禁止**、SQLAlchemy ORMによるモデル定義（1ファイル最大400行制限）。
- **DTO・パーサー物理分離（PAT-CODE-001）**: DTOおよびパーサーは独立モジュールへ物理分離し、Controller層はオーケストレーションに専念させる。

### 4.4 🎨 UI/UXデザイナー (`ui-designer`)
- **Anti-God Component の徹底**: 1ファイル最大250行制限、コンポーネント内直書きモックの原則禁止（MSW必須）。
- **デイライト視認性担保（PAT-UI-001）**: セマンティックデザイントークンまたはTailwind明暗ペア指定を必須とする。

### 4.5 🛡️ 品質監査スペシャリスト (`qa-engineer`)
- **3大レビューの厳格監査**: 定常コア8項目およびプロファイル別観点からの機械的合否判定。
- **Semantic Auditor 責務**: 知見原票に対する3段階意味的整合性監査（Gate 1〜4、**pattern_id 重複衝突排除**）の実行。
- **【コード直接改変禁止】** システム本体コードに不具合を発見した場合は勝手に修正せず、Unified Diff案をコンダクターへ報告する。
