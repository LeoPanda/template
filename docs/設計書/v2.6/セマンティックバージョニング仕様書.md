## 1. はじめに

### 1.1 背景と課題
AI駆動システム開発テンプレート（`system-dev-pipeline`）は、V2.0〜V2.4 を通じて自律開発・監査・知見合流の仕組みを高度に確立してきた。
本仕様書は、システムソフトウェア、管理台帳、Gitタグ、改訂依頼番号、ドキュメント管理フォルダの全領域における統一バージョニング仕様を策定・規定することを目的とする。

---

## 2. 公式セマンティックバージョニング (SemVer 2.0.0) 基準原則

本パイプラインは、[Semantic Versioning 2.0.0](https://semver.org/lang/ja/) の基本原則を厳格に採用する。

### 2.1 基本構造
バージョン番号は **`MAJOR.MINOR.PATCH`** の形式をとる。

$$\text{Version} = \text{MAJOR} . \text{MINOR} . \text{PATCH}$$

- **MAJOR (メジャー)**: 後方互換性のない破壊的変更が行われた場合にインクリメント。
- **MINOR (マイナー)**: 後方互換性のある機能追加・仕様拡張が行われた場合にインクリメント。
- **PATCH (パッチ)**: 後方互換性のあるバグ修正・小規模改善が行われた場合にインクリメント。

## 3. 領域別バージョニング表記マトリクス

| 区分 | 適用対象ファイル・領域 | フォーマット規約 | 具体例 | 制定動機と効果 |
| :--- | :--- | :--- | :--- | :--- |
| **① ソフトウェア本体** | `.env`<br>`package.json`<br>`Cargo.toml`<br>`main.py` | **`MAJOR.MINOR.PATCH`**<br>(数値3桁、先頭 `v` なし) | `APP_VERSION=1.0.0`<br>`"version": "1.0.0"`<br>`version = "1.0.0"` | 言語エコシステム・パッケージマネージャーのバリデーション準拠。 |
| **② 管理台帳・Git・UI** | `PROJECT_STATE.md`<br>Git コミット / タグ<br>UI バッジ（ヘッダー等） | **`vMAJOR.MINOR.PATCH`**<br>(小文字 `v` ＋ 数値3桁) | `- **現行バージョン**: v1.0.0`<br>`Release v1.0.0`<br>`git tag v1.0.0`<br>バッジ: `v1.0.0` | 業界標準 (De facto Standard) の Git タグ運用および UI 表示の統一。 |
| **③ 改訂依頼番号** | 改訂依頼・管理票<br>`/revise-log/` 文書 | **`MAJOR.MINOR.xxx`**<br>(通番3桁連番) | `1.0.001`, `1.0.002`<br>`2.0.001` | パッチ改訂でも番号肥大化を防ぎつつ整然としたソート性を確保。 |
| **④ ドキュメント管理** | `docs/設計書/vn.m/`<br>`/revise-log/vn.m/`<br>改訂レポート/テストレポート | **`vn.m`**<br>(小文字 `v` ＋ 2桁) | `docs/設計書/v2.4/`<br>`/revise-log/v1.0/`<br>`docs/v1.0改訂レポート.md` | 大文字 `V` を廃止し小文字 `v` に統一。ドキュメント管理の簡便性を両立。 |
| **⑤ リリース処理保護** | `skills/dev-git-release` | 先頭サニタイズ処理 | `CLEAN=$(echo $RAW \| sed -E 's/^[vV]+//')`<br>`git tag "v${CLEAN}"` | `.env` に `V2.0` や `v1.0.0` が記載されていても二重プレフィックス（`vV2.0`）を完全防御。 |
