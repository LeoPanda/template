# コンダクターによるサブエージェント動的登録フォールバック（Dynamic Fallback）仕様書

本ドキュメントは、[サブエージェント構文・ツール権限体系とプラグイン定義の整合性に関する検討課題.md](template/docs/検討課題/V2.0/サブエージェント構文・ツール権限体系とプラグイン定義の整合性に関する検討課題.md) の検討課題4に基づき、プラグイン静的定義（`plugin.json`）のエージェントが実行環境セッションに未ロードである場合に、司令塔であるプロジェクトコンダクターが自律的にエージェント定義を解析・動的登録（`define_subagent`）し、安全にタスクを委譲・実行するためのフォールバック仕様を規定する。

---

## 1. 背景と目的

Antigravity プラグイン（`system-dev-pipeline`）では、マニフェスト（`plugin.json`）の `agents` フィールドにサブエージェント（`architect`, `ui-designer`, `qa-engineer`）を宣言し、`.agents/plugins/system-dev-pipeline/agents/*.md` に定義を配置する。

しかし、以下の要因によりランタイムのシステムプロンプト内 `<subagents>`（利用可能サブエージェント一覧）に未登録となる状況が想定される：
1. プラグインのインストール直後やキャッシュ未更新状態でのセッション開始
2. サブエージェントの定義ファイルを更新したが、セッションに動的反映されていない場合
3. プラグインの自動ロードが無効化または限定されている環境での実行

このような状況下でも開発パイプラインの停止を防ぎ、コンダクターが自律的に状況を判定して `define_subagent` を呼び出し、正常にサブエージェント委譲へ移行できる耐障害性（レジリエンス）の高い動的登録フォールバック機構を定義する。

## 2. 動的登録フォールバックの全体シーケンス

```mermaid
sequenceDiagram
    autonumber
    actor User as ユーザー
    participant Conductor as 👑 プロジェクトコンダクター
    participant FS as ローカルFS (agents/*.md)
    participant Engine as Antigravity ランタイム
    participant Subagent as サブエージェント (例: architect)

    User->>Conductor: タスク実行指示 (例: PHASE 2 要件定義)
    Note over Conductor: 委譲先サブエージェントを決定 (TypeName: "architect")
    Conductor->>Conductor: コンテキストの <subagents> 一覧を検査

    alt TypeName が Available subagents に存在する場合 (通常フロー)
        Note over Conductor: 通常呼び出し
    else TypeName が未登録の場合 (動的フォールバックフロー)
        Note over Conductor: ⚠️ 動的登録フォールバック開始
        Conductor->>FS: view_file (.agents/plugins/system-dev-pipeline/agents/architect.md)
        FS-->>Conductor: ファイル内容返却 (YAML Frontmatter + システムプロンプト)
        Conductor->>Conductor: Frontmatter (name, description, flags, defaults) を解析
        Conductor->>Engine: define_subagent 実行<br>(name, description, system_prompt, enable_*_tools)
        Engine-->>Conductor: 登録完了通知
    end

    Note over Conductor: invoke_subagent の引数決定<br>(Model/Workspace は指定があれば優先、なければ Frontmatter の default を適用)
    Conductor->>Engine: invoke_subagent 実行 (TypeName, Role, Model, Workspace, Prompt)
    Engine->>Subagent: サブエージェント起動・プロンプト投入
    Subagent->>Subagent: 自律作業 (二重防御ガードレール遵守)
    Subagent-->>Conductor: 作業完了サマリ返却 (send_message)
    Conductor->>User: 結果報告・次フェーズ案内
```

## 3. 詳細判定ロジックと実行手順

### Step 1: 委譲前のアクティブ確認（Discovery Check）
コンダクターはタスクをサブエージェントに委譲する直前に、自身のシステムプロンプト内 `<subagents>` ブロックを参照し、対象となる `TypeName`（`architect`, `ui-designer`, `qa-engineer` 等）が存在するかを確認する。

- **存在する場合**: Step 4（`invoke_subagent`）へ直行する。
- **存在しない場合**: Step 2（エージェント定義ファイルの取得）へ進む。

### Step 2: 静的定義ファイルの取得とパース
コンダクターは `view_file` ツールを用いて、対象エージェントの Markdown 定義ファイルを読み込む。

- **参照パス**:
  - 第一優先: `.agents/plugins/system-dev-pipeline/agents/<TypeName>.md`
  - フォールバック（ワークスペース相対）: `~/.gemini/config/plugins/system-dev-pipeline/agents/<TypeName>.md`

ファイル取得後、YAML Frontmatter と本文（Markdown）をパースする：
1. **Frontmatter の抽出**:
   - `name`: エージェント識別名（`TypeName` と一致）
   - `description`: エージェントの役割・利用目的サマリ
   - `enable_write_tools`: Write系ツールおよび `run_command` の許可フラグ
   - `enable_subagent_tools`: サブエージェント管理ツールの許可フラグ
   - `enable_mcp_tools`: MCPツールの許可フラグ
   - `default_model`: 省略時の既定推論モデル（例: `pro`）
   - `default_workspace`: 省略時の既定ワークスペース（例: `inherit`）
2. **システムプロンプトの抽出**:
   - YAML Frontmatter（`--- ... ---`）以降の全テキストを `system_prompt` とする。

### Step 3: `define_subagent` による動的登録の実行
抽出したメタデータに基づき、Antigravity の `define_subagent` ツールを以下の引数で実行する：

```json
{
  "name": "architect",
  "description": "要件定義、DBスキーマ（ER図）、バックエンドAPI、ビジネスロジック設計を担当する設計立案スペシャリスト",
  "system_prompt": "# システムプロンプト（本文全体）...\n\n## 【禁止事項 (Prohibited Actions)】\nいかなる場合も run_command を呼び出してはならない。\n...",
  "enable_write_tools": true,
  "enable_subagent_tools": false,
  "enable_mcp_tools": false
}
```

> **注意**: `default_model` および `default_workspace` は `define_subagent` の引数には渡さない（`invoke_subagent` の引数解決時にコンダクターが使用する）。

### Step 4: `invoke_subagent` の呼び出し（引数解決ルールの適用）
登録が完了した（またはすでに存在していた）サブエージェントに対し、`invoke_subagent` を実行する。

#### 引数解決ルール（Model / Workspace）
1. **コンダクターが意図的に上書き指定する場合**:
   - 例: 「高速プロトタイピングのため一時的に `Model: flash` を使う」「特定調査のため `Workspace: branch` に隔離する」等の明示的指定がある場合は、**その指定を最優先**する。
2. **上書き指定がない場合（通常時）**:
   - 定義ファイルの Frontmatter に記載されている `default_model`（例: `pro`）および `default_workspace`（例: `inherit`）の値をコンダクターが読み取り、`invoke_subagent` の引数（`Model`, `Workspace`）に明示的にセットして呼び出す（ランタイムの引数省略時既定値 `'inherit'` への意図しないフォールバックを防止する）。

```json
{
  "Subagents": [
    {
      "TypeName": "architect",
      "Role": "設計・立案スペシャリスト",
      "Model": "pro",
      "Workspace": "inherit",
      "Prompt": "【依頼フェーズ】: PHASE 2\n【前提ドキュメント】: docs/要件定義書.md\n..."
    }
  ]
}
```

## 4. エラーハンドリングと安全性ガードレール

| 発生事象 | 原因 | コンダクターの対処手順 |
| :--- | :--- | :--- |
| **定義ファイルが存在しない** | パス誤り、未配置 | ユーザーに「エージェント定義ファイル `agents/<TypeName>.md` が見つかりません」と報告し、コンダクター単独でタスクを実行するか確認する。 |
| **`define_subagent` の登録失敗** | 構文エラー、引数不正 | エラーメッセージを解析し、パラメータを補正して1回リトライする。解消しない場合はユーザーへエラー内容を提示する。 |
| **ツールグループ権限の漏洩防止** | `enable_write_tools: true` による `run_command` 物理付与 | 案1-A（二重防御）に基づき、`system_prompt` に厳格な禁止事項が含まれていることを確認した上で登録する。 |
