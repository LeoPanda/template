## 1. 移行完了判定チェックリスト (Migration Checklist)

既存プロジェクトの v3.0.1 移行改訂が完全に完了したかを客観的に確認するためのチェックリストです。

### 1.1 パイプライン共通資産・台帳 (Pipeline Assets & State)
- [ ] `scripts/harness_guard.py` が v3.0.0/v3.0.1 版に更新され、実行権限（`chmod +x`）が付与されている。
- [ ] `scripts/state_manager.py` が v3.0.0/v3.0.1 版に更新され、実行権限が付与されている。
- [ ] `scripts/traceability_checker.py` が v3.0.0/v3.0.1 版に更新され、実行権限が付与されている。
- [ ] `project_state.json` の `schema_version` が `"3.0.0"` になっている。
- [ ] `project_state.json` に `project_metadata.capability_traits`（配列）が定義されている。

- [ ] `project_state.json` の `revisions.rev_phases` が `REV_1`〜`REV_6` の6段階定義になっている。

### 1.2 ドキュメント衛生・形式 (Documentation Hygiene)
- [ ] `docs/設計書/Current/` 直下に、個別バージョン名を含むファイル（例: `*V2.6*.md`）が存在しない（`docs/設計書/v2.6/` 等へ退避済）。
- [ ] `docs/設計書/Current/` 直下に、一時ファイル（`tmp_*`, `backup_*`, `old_*` 等）が存在しない。
- [ ] `docs/設計書/` 直下に、Current 配下に未整理の浮遊ファイルが存在しない。
- [ ] すべての Markdown ファイル内の Mermaid ダイアグラムにおいて、括弧を含む矢印ラベルがダブルクォートで囲まれている（`-->|"ラベル(説明)"|`）。
- [ ] 設計書内のハイパーリンクが絶対パス（`file:///` や `/Users/...`）ではなく、相対パス（`../設計書.md` 等）になっている。

### 1.3 システム本体コード (System Code & Hard Gate)
- [ ] フロントエンドコード（`frontend/src/`）に 350行を超えるハードブロック対象ファイルが存在しない（250〜350行は WARN）。
- [ ] バックエンドコード（`backend/`）に 550行を超えるハードブロック対象ファイルが存在しない（400〜550行は WARN）。
- [ ] Python コード内に空関数・縮退実装（`pass`, `...`, `raise NotImplementedError` のみ）が存在しない（`HG-010`）。
- [ ] React / JSX 内に空ハンドラ（`onClick={() => {}}`）が存在しない（`HG-010`）。
- [ ] 本番コード領域に直書きモック（`mockUsers`, `dummyData`, `generate_mock_*`, `dummy_*`, `testsrc`, `sine=`）が存在しない（`HG-002`）。
- [ ] Python の `except` 節内でモックやダミーを返却するサイレントフォールバックが存在しない（`HG-002`）。

### 1.4 テストコード・RTM・証跡 (Tests, Traceability & Evidence)
- [ ] `docs/plans/シナリオテスト計画書.md` をテスト実績カウントから除外しても、全要件（`[REQ-*]`）がテストコードへ直結している。
- [ ] すべての `[REQ-*]` が、有効なテスト関数ノード内（docstring）または直前3行コメントに配置されている。
- [ ] トートロジーテスト（`assert True`, `assert 1 == 1`, 実呼出のないローカル自己代入テスト）が排除されている。
- [ ] 異常系テスト比率が **20.0% 以上** を達成している。
- [ ] コードカバレッジが **70.0% 以上**（設定されている場合）を達成している。
- [ ] Stage 1.5 スモークテスト（FastAPI `TestClient` による物理ファイル生成検証）が実装されている。
- [ ] `metrics/qa_runtime_evidence.json` が `traceability_checker.py --mode full` により SHA-256 署名付きで生成されている。
- [ ] `.env` の `VITE_ENABLE_MOCK=false`（モックOFF）状態で実結合 E2E テストが実行されている。

### 1.5 改訂ライフサイクル (Revision Lifecycle & Invariants)

## 2. トラブルシューティング（Trap & Pitfalls）

移行作業中によく遭遇するエラー、その発生原因、および具体的な解決方法を解説します。

---

### エラー①: `[READINESS-HG] Harness Guard 規約違反が検出されました`

```text
❌ [READINESS BLOCKED] REV-4 実機レビュー突入前提条件を満たしていません:
  - [READINESS-HG] Harness Guard 規約違反が検出されました:
    🚨 [HG-010] [BLOCK] backend/services/export.py:45: 明白な空実装・未実装関数を検出 (export_pdf: pass)
```

- **原因**: REV-4（実機レビュー）突入前に `harness_guard.py --all` が実行され、行数超過、空実装、モック残留などの違反が検出された。
- **解決法**:
  1. `python3 scripts/harness_guard.py --all` を直接実行して詳細な違反箇所を特定する。
  2. 指摘された箇所の空実装を実ロジックへ修正するか、行数超過コンポーネントを分割する。
  3. 違反が 0件になったことを確認後、再度 `verify-review-readiness` を実行する。

---

### エラー②: `[READINESS-DOC] docs/設計書/Current/ 直下に一時ファイル・旧版ファイルが検出されました`

```text
❌ [READINESS BLOCKED] REV-4 実機レビュー突入前提条件を満たしていません:
  - [READINESS-DOC] docs/設計書/Current/ 配下に一時ファイルまたは旧版ファイルが残存しています:
    - AI駆動システム開発手順書V2.6.md
    - tmp_screen_spec.md
```

- **原因**: `docs/設計書/Current/` 直下に、旧バージョンのファイル名（`V2.6` 等）や一時ファイル（`tmp_*`, `backup_*`）が残っている。
- **解決法**:
  1. 旧版ファイルは過去バージョン用フォルダ（例: `docs/設計書/v2.6/`）へ移動する。
  2. 一時ファイルやバックアップファイルは削除するか、適切な名称に変更して Current 配下に配置する。
  3. `docs/設計書/Current/` には「システム現行バージョンの正本設計書のみ」が配置されている状態にする。

---

### エラー③: `[RTM BLOCKED] 要件 [REQ-xxx] が未検証です`（テスト内にあるのに認識されない）

```text
🚨 [RTM BLOCKED] テスト未検証の要件が 2 件存在します:
  - [REQ-F03]: PDFエクスポート機能
  - [REQ-NF01]: 応答時間1秒以内
```

- **原因**:
  1. `docs/plans/シナリオテスト計画書.md` 内にしか `[REQ-*]` が書かれていない（計画書はカウント除外された）。
  2. テストファイル（`.py`, `.ts`）内にあるが、**テスト関数の外側（ファイル先頭や import 付近）に書かれている**。
  3. テスト関数がトートロジー（`assert True` のみ等）と判定されて無効化された。
- **解決法**:
  1. テスト関数の **docstring 内**、またはテスト関数の **直前3行以内のコメント** に `[REQ-xxx]` を記述する。
  ```python
  # OK (直前コメント)
  # [REQ-F03] PDFエクスポートの正常系検証
  def test_export_pdf_success():
      ...
  ```
  2. 実コードの呼び出しとアサーションを伴うテストに修正する。

---

### エラー④: `[RTM BLOCKED] 異常系テスト比率が基準未満です (12.5% < 基準 20.0%)`

- **原因**: テストケース全体に占める異常系・エラー系テストの比率が 20% 未満である。
- **解決法**:
  1. バリデーションエラー、認証失敗、タイムアウト、404/500 エラーなどの異常系テストを追加する。
  2. 追加したテスト関数の docstring または直前コメントに `@test_type: negative` または `abnormal`, `error`, `invalid`, `failure`, `異常系` を明記する。
  ```python
  # @test_type: negative
  # [REQ-F01] パスワード不一致時の認証エラー
  def test_login_invalid_password():
      ...
  ```

---

### エラー⑤: `[HG-002] Pythonサイレントモックフォールバックを検出 (except節内でモック/ダミー返却)`

```text
🚨 [HG-002] [BLOCK] backend/services/weather.py:32: Pythonサイレントモックフォールバックを検出 (except節内でモック/ダミー返却: return dummy_weather_data())
```

- **原因**: 外部API通信などの `try-except` 節において、エラー発生時に例外を投げずにダミーデータを返却している。
- **解決法**:
  - 本番運用時の障害隠蔽を防ぐため、サイレントフォールバックを廃止し、カスタム例外をスロー（Fail-Fast）するか、適切なエラーハンドリングを行う。
  ```python
  # 修正前 (NG)
  except Exception:
      return dummy_weather_data()

  # 修正後 (OK)
  except ExternalApiException as e:
      logger.error(f"Weather API failed: {e}")
      raise ServiceUnavailableException("気象データ取得に失敗しました")
  ```

---

### エラー⑥: `[HG-011] Scope Guard Violation: 非開発モードまたは改訂未起票状態でのシステム本体コード改変`

```text
🚨 [HG-011] [BLOCK] backend/main.py: Scope Guard Violation: 非開発モードまたは改訂未起票状態でのシステム本体コード改変を検出しました
```

- **原因**: `project_state.json` のセッションモードが `CONTENT_PRODUCTION` であるか、またはステータスが `PRODUCTION_ACTIVE` かつ改訂が起票されていない状態で、システム本体コード（`backend/`, `frontend/`, `docs/設計書/Current/`）を編集した。
- **解決法**:
  - システム改訂パイプラインを起票してシステム開発モードへ昇格する：
  ```bash
  python3 scripts/state_manager.py start-revision --id "REV-20261112-001" --title "機能改訂"
  ```
  - またはセッションモードを明示的に切り替える：
  ```bash
  python3 scripts/state_manager.py set-mode --mode DEV_PIPELINE
  ```

---

### エラー⑦: `[INV-QA-01] SHA-256署名チェックサム検証に失敗しました (改ざん・不整合検知)`

```text
❌ [HARD GATE BLOCKED] 改訂完了前提条件 (Invariants) 違反を検出しました:
  - [INV-QA-01] metrics/qa_runtime_evidence.json のSHA-256署名チェックサム検証に失敗しました (改ざん・不整合検知)。
```

- **原因**: `metrics/qa_runtime_evidence.json` をエージェントや開発者がテキストエディタで直接手動編集したため、残余フィールドから算出される SHA-256 ハッシュ値と署名値が一致しなくなった。
- **解決法**:
  - 手動編集は絶対に行わず、`traceability_checker.py --mode full` を再実行して自動的に正しい署名を付与・再生成させる：
  ```bash
  python3 scripts/traceability_checker.py --mode full
  ```

---

### エラー⑧: `[INV-REV-04] REV-4 ユーザー実機レビュー承認が記録されていません`

```text
❌ [HARD GATE BLOCKED] 改訂完了前提条件 (Invariants) 違反を検出しました:
  - [INV-REV-04] REV-4 ユーザー実機レビュー承認が記録されていません (revisions.rev_phases.REV_4.approved != True)。
```

- **原因**: REV-4 の実機レビューにおいて、ユーザーからの明示的承認コマンドが実行されていない。
- **解決法**:
  - 実機動作の確認完了後、以下の承認記録コマンドを実行する：
  ```bash
  python3 scripts/state_manager.py record-approval --rev REV_4 --approver "User" --comment "実機レビュー合格"
  ```

---

### エラー⑨: コミット前フックで Mermaid 構文安全規約（`PAT-DOC-003`）に引っかかる

```text
🚨 [PAT-DOC-003] [BLOCK] docs/設計書/Current/アーキテクチャ設計書.md:45: Mermaid 矢印ラベルにクォートされていない括弧が含まれています: -->|リクエスト(同期)|
```

- **原因**: Mermaid の矢印ラベルに丸括弧 `()` や角括弧 `[]` などの特殊記号がそのまま含まれている。
- **解決法**:
  - ラベル全体をダブルクォーテーション `"` で囲む：
  ```mermaid
  %% 修正: ダブルクォートで囲む
  Client -->|"リクエスト(同期)"| Server
  ```

## 3. まとめ

本トラブルシューティング集に記載された各エラーは、すべて「見せかけのテスト合格」「モックの意図せぬ本番流出」「文書の放置」という**AI駆動開発特有のハーネス死角を機械的に防止するために設置された安全装置**です。

エラーに遭遇した際は、場当たり的な回避（スクリプトの一時的改変や自己申告JSONの書き換え）を行わず、本ガイドに沿って根本原因を解消してください。これにより、極めて高い堅牢性と品質を備えたプロジェクト運用が実現します。
