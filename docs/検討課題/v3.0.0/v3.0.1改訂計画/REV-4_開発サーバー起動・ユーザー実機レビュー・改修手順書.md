## 1. フェーズ目的

`REV-3` においてモック完全解除、ドキュメント衛生整理、および `verify-review-readiness` ゲートを通過した清潔な動作環境において、ユーザー自身による実機・実動作レビューを受け、発見された課題や改善要望を対話的に改修しきる。

## 2. 標準プロトコル

### 2.1 実機レビュー開始前の前提条件確認
- 👑 コンダクターは、必ず `python3 scripts/state_manager.py verify-review-readiness` が PASS していることを確認した上で、開発サーバー起動およびユーザーへの実機レビュー要請を行う。
- 万一 `verify-review-readiness` でエラーが検出された場合、開発サーバーの起動およびユーザーへの提示はハードブロックされる。

### 2.2 本改訂（v3.0.1）における実施タスク
- [x] **T4-1: 実結合モードでの動作デモおよび実機提示**
  - 改修されたスクリプト群（`harness_guard.py`, `state_manager.py`, `traceability_checker.py`）の動作結果、および整然と整理されたドキュメント群（`docs/設計書/Current/`）をユーザーへ提示。
  - 新設された `verify-review-readiness` コマンドの実行ログ、および署名付き `qa_runtime_evidence.json` の出力を提示し、実機確認を依頼する。
- [x] **T4-2: 対話的改修ループ (Interactive Refinement Loop)**
  - ユーザーから指摘された不備や調整要望について、即座に修正を実施。
  - 修正都度、`harness_guard.py --all` および関連テストを再実行し、再度ユーザーに確認を仰ぐ。
- [x] **T4-3: ユーザー実機レビュー承認の記録**
  - ユーザーから最終的な「動作確認OK」の承認を得た後、コンダクターが以下を実行して承認を記録する：
    ```bash
    python3 .agents/plugins/system-dev-pipeline/scripts/state_manager.py record-approval --phase REV_4
    ```
  - **承認記録**: 2026-11-10T16:30:15+09:00 にユーザーより明示承認を受領（「改訂計画REV-4を承認します。T4-3を処理し、次のREV-5を実行して下さい。」）。REV-4 完了を確認。
