## 2. 標準プロトコル（一般アプリケーション開発時 & 本テンプレート改訂時）

### 2.1 一般システム開発プロジェクト（Profile A〜D）における `REV-4` 標準手順
1. **実結合モード（モックOFF）での開発サーバー起動**:
   - 👑 コンダクターが `VITE_ENABLE_MOCK=false`（実データ結合モード）でバックエンドおよびフロントエンド開発サーバー（Docker Compose / Uvicorn + Vite dev / `cargo tauri dev`）を起動する。
2. **ユーザーへの実機レビュー要請**:
   - 起動したローカルURL（例: `http://localhost:5173`）またはデスクトップアプリ画面、および今回の改訂で重点確認すべき操作シナリオをユーザーへ提示し、実機テストレビューを依頼する。
3. **対話的改修ループ（Interactive Refinement Loop）**:
   - ユーザーの実機操作で発見された不具合、UI/UXの違和感、エッジケースの挙動不備について、サブエージェント（`backend-engineer`, `ui-designer`, `architect`）へ委譲して即時改修する。
   - 改修都度、コンテナ再構成・ホットリロード反映および `harness_guard.py --all` と回帰テストを実行し、再度ユーザーに実機確認を仰ぐ。
4. **ユーザー実機レビュー承認の記録（Gate Lock 解除）**:
   - ユーザーから「実機動作OK」の承認を得た後、コンダクターが `python3 scripts/state_manager.py record-approval --phase REV_4` を実行し、台帳に承認日時を記録する（この記録がない限り、`REV-6` の `complete-revision` は `[INV-REV-04]` で機械遮断される）。
