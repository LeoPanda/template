---

## 1. フェーズ目的

REV-3 の `verify-review-readiness` 完全通過（Live Invariant Probe 合格）を前提として、実機稼働モードで改修内容の動作確認を行い、ユーザーに実機レビューを提示する。ユーザーからのフィードバックに応じた対話的改修を実施し、承認を確定・記録する。

---

## 2. 実施タスクリスト

- [x] **T4-1: REV-4 突入前提条件の確認 (インターロック)**
  - `python3 scripts/state_manager.py set-phase REV_4` を実行し、`verify-review-readiness` の合格状態が台帳に正しく反映されていることを確認する。
- [x] **T4-2: 開発環境の実機起動と動作確認**
  - 改修後のパイプラインスクリプトおよび共通スケルトンを用いたデモプロジェクトを実機起動する。
  - Live Invariant Probe が実際に起動テストを実施し、本番起動コマンドで正常に 200 OK が返る挙動をユーザーへ実演・提示する。
- [x] **T4-3: ユーザー実機テストレビュー要請**
  - ユーザーに対し、以下の確認項目を明示して実機レビューを要請する：
    1. `verify-review-readiness` 実行時に、サーバーがバックグラウンド起動して DB 疎通テストが実施される様子
    2. パス不正等の環境異常時に、サーバー起動ログがキャプチャされて即時遮断される様子
    3. 共通スケルトンでの環境自動適応（`/app/data` ➔ ローカル `data/` フォールバック）の動作
- [x] **T4-4: ユーザー指摘事項の対話的改修・再検証ループ**
  - ユーザーからの指摘や改善要望があった場合、設計・実装の改修をオーケストレーションする。
  - 改修後は再度 `harness_guard.py` および `verify-review-readiness` を実行し、品質を維持する。
- [x] **T4-5: ユーザー実機承認の記録 (Audit Gate)**
  - ユーザーから「実機レビュー承認」の明示的受領を確認する。
  - `python3 scripts/state_manager.py record-review-approval` を実行し、承認タイムスタンプおよび承認ハッシュを台帳（`project_state.json`）へ不可逆記録する。

---

## 3. 完了判定条件（Exit Criteria）

- ユーザー実機レビューが完了し、指摘事項がすべて解決されていること。
- `state_manager.py record-review-approval` によりユーザー承認が台帳へ記録されていること。
