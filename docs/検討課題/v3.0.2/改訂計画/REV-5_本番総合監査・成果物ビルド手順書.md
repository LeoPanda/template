- **改訂依頼番号**: `v3.1.0` (`PLAN-V310-001`)

- **親計画書**: [00_v3.1.0改訂基本計画書.md](./00_v3.1.0改訂基本計画書.md)

---

## 1. フェーズ目的

REV-4 のユーザー実機レビューで発生した改修差分を設計書へ完全反映し、第2段階ドキュメント多次元相互整合性監査（`dev-doc-reviewer`）、コード品質レビュー（`dev-review-code`）、およびシステム総合レビュー（`dev-review-system`）の 3重レビューゲートを完全通過させ、本番成果物をビルドする。

---

## 2. 実施タスクリスト

- [x] **T5-1: 対話的改修差分の設計書反映**
  - REV-4 のユーザーレビューおよび対話的改修で決定した仕様変更・パラメータ調整を、正本設計書群（`docs/設計書/Current/`）へ正確に逆反映する。
- [x] **T5-2: 第2段階 ドキュメント多次元相互整合性監査 (Semantic Cross-Check)**
  - `dev-doc-reviewer` を実行し、要件定義 ⇔ 基本設計書 ⇔ 実装コード間の多次元相互整合性を検証する。
  - 矛盾や記述漏れが 0 件であることを確認する。
- [x] **T5-3: コード品質レビュー (dev-review-code)**
  - 実装コード全域の品質、DRY原則、2段階行数制限、モック混入排除、型整合性を監査する。
  - レビュー結果判定が `CLEAN` であることを確認する。
- [x] **T5-4: システム総合レビュー (dev-review-system)**
  - 本番稼働耐性、セキュリティ、平文シークレット排除、Alembic起動保証、Live Probe 耐性を総合監査する。
  - レビュー結果判定が `RELEASE APPROVED` であることを確認する。
- [x] **T5-5: 本番成果物のビルドと整合性検証**
  - パッケージビルド、スケルトン整合性チェックを実行し、配布成果物に欠損がないことを確認する。

---

## 3. 完了判定条件（Exit Criteria）

- 第2段階ドキュメント多次元相互整合性監査が PASS であること。
- `dev-review-code` 判定が `CLEAN` であること。
- `dev-review-system` 判定が `RELEASE APPROVED` であること。
- 本番ビルド成果物が正常に生成されていること。
