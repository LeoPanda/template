# サブエージェント構文・ツール権限体系とプラグイン定義の整合性に関する検討課題

本ドキュメントは、[エージェント設計書.md](template/docs/V2.0/エージェント設計書.md) に記載されているツール指定と、Antigravityの実際のサブエージェント定義機能（`define_subagent` API および `.agents/plugins/system-dev-pipeline/agents/*.md`）におけるサポート構文との対応関係を確定させるために必要な検討課題を整理した技術仕様書・論点整理書である。

### 【検討課題 1】ツールグループ制約下における権限分離・ガードレール方式の確定 【決定：案1-A採用】

#### 課題の背景
Antigravity のサブエージェント定義 API（`define_subagent`）では、ツールは個別の関数名ではなく、以下の3つのグループフラグで制御される：
1. **デフォルト（指定不要）**: Read系ツール（`view_file`, `grep_search`, `find_by_name`, `list_dir`, `search_web`）および通信（`send_message`）
2. **`enable_write_tools` (boolean)**: Write系ツール（`write_to_file`, `replace_file_content`）**＋ シェルコマンド実行（`run_command`）**
3. **`enable_subagent_tools` (boolean)**: サブエージェント操作（`define_subagent`, `invoke_subagent`, `manage_subagents`）
4. **`enable_mcp_tools` (boolean)**: MCPツール群

📐 `architect` はドキュメントを作成・編集するため `enable_write_tools: true` が必須であるが、これに伴い **`run_command` も物理的に利用可能となってしまう**。

#### 決定事項（案 1-A: 二重防御方式の採用）
- **フラグレベルの許可**:
  - `architect`, `ui-designer`, `qa-engineer` の3者すべて `enable_write_tools: true` とする。
- **システムプロンプトレベルの厳格な禁止（二重防御ガードレール）**:
  - `architect` のシステムプロンプト最上部に **「【禁止事項 (Prohibited Actions)】いかなる場合も `run_command` を呼び出してはならない」** を明記し、LLMの推論レベルで確実にブロックする。
  - 同様に、`ui-designer` と `qa-engineer` にも許可されたコマンド以外の破壊的操作（Gitコミット・マージ・プッシュ、デプロイ、DB上書き等）を禁止事項として徹底する。

### 【検討課題 2】プラグイン静的定義ファイル（`agents/*.md`）のフロントマター仕様策定 【決定】

#### 課題の背景
`.agents/plugins/system-dev-pipeline/agents/<agent-name>.md` を配置するにあたり、Antigravity プラグインシステムが解釈可能かつ `define_subagent` と相互変換しやすい YAML Frontmatter のスキーマを統一する必要がある。

#### 決定事項（Frontmatter構文仕様）
1. **キー名の完全一致（検討課題2.1方針）**:
   - Frontmatter のキー名は、可能な限り `define_subagent` の引数名（`name`, `description`, `enable_write_tools`, `enable_subagent_tools`, `enable_mcp_tools`）と一致させる。
2. **既定値メタデータの内包（検討課題2.2方針）**:
   - `default_model` や `default_workspace` など、既定の挙動はあらかじめ Frontmatter にメタデータとして含めておき、エージェントごとのデフォルトの挙動を統一しておく。

#### 確定構文スキーマ（Markdown + YAML Frontmatter）
```markdown
---
name: architect
description: "要件定義、DBスキーマ（ER図）、バックエンドAPI、ビジネスロジック設計を担当する設計立案スペシャリスト"
enable_write_tools: true
enable_subagent_tools: false
enable_mcp_tools: false
default_model: pro
default_workspace: inherit
---

# システムプロンプト（本文）
あなたはソフトウェアアーキテクトおよびビジネスアナリストです。
...
```

### 【検討課題 3】`invoke_subagent` 呼び出し時の引数責務の標準化 【決定】

#### 課題の背景
Antigravity のランタイムにおいて、推論モデル（`Model`）やワークスペース（`Workspace`）は `invoke_subagent` ツールの引数として渡される。

#### 決定事項（引数責務と優先度ルール）
- **デフォルト値の自動適用**:
  - 検討課題2.2において Frontmatter に `default_model`, `default_workspace` を定義しているため、あえてデフォルトを外す必要がある時以外は、呼び出し側（コンダクター）で `Model` や `Workspace` を個別指定する必要はない。
- **明示指定の絶対優先**:
  - ただし、呼び出し側で `Model` や `Workspace` の指定がある場合には、**必ずこれを最優先（オーバーライド）** して適用する。

### 【検討課題 4】コンダクターによる動的登録フォールバック（Dynamic Fallback）仕様 【決定】

#### 課題の背景
プラグインの `plugin.json` にサブエージェントを登録していても、セッション状態や環境差異によって `<subagents>`（Available subagents）に未ロードの場合がある。この際にコンダクターが自律的に動的登録してタスクを続行できるフォールバック手順を策定した。
